## H-01: Godot 4.6.2 インストール

### 目的
プロジェクトのエンジンを `docs/02_services/version_policy.md` §9.1 で確定した Godot 4.6.2 で固定し、`--headless --import` および各プロト実行を可能にする。

### 前提
- Windows 11
- ディスク空き容量: 1 GB 以上
- 管理者権限: **不要**(Godot はポータブルアプリ)

### 手順

#### 方式 A: 公式 ZIP を手動展開(推奨・確実)

##### A-1. 公式サイトからダウンロード
ブラウザで公式 Releases ページを開く:

```
https://godotengine.org/download/archive/4.6.2-stable/
```

または GitHub Releases:

```
https://github.com/godotengine/godot/releases/tag/4.6.2-stable
```

ダウンロード対象: **`Godot_v4.6.2-stable_win64.exe.zip`**(.NET なし版、約 100 MB)

> .NET 版(`Godot_v4.6.2-stable_mono_win64.zip`)は本作で C# を採用しないため不要(`docs/02_services/version_policy.md` §9.2)。

##### A-2. 展開
任意のフォルダに展開。推奨先:

```powershell
# PowerShell
$dest = "$env:USERPROFILE\Apps\Godot"
New-Item -ItemType Directory -Path $dest -Force
# ダウンロードした zip のパスに合わせて調整
Expand-Archive -Path "$env:USERPROFILE\Downloads\Godot_v4.6.2-stable_win64.exe.zip" -DestinationPath $dest -Force
```

展開後、`%USERPROFILE%\Apps\Godot\Godot_v4.6.2-stable_win64.exe` が存在すること。

##### A-3. PATH に追加(コマンドラインから godot コマンドで呼び出すため)

エクスプローラから手動で:
1. 「設定」→「システム」→「バージョン情報」→「システムの詳細設定」→「環境変数」
2. ユーザー環境変数の `Path` を編集 → `%USERPROFILE%\Apps\Godot` を追加 → 保存

または PowerShell で(管理者不要、ユーザー環境変数):

```powershell
[Environment]::SetEnvironmentVariable(
    "Path",
    [Environment]::GetEnvironmentVariable("Path", "User") + ";$env:USERPROFILE\Apps\Godot",
    "User"
)
```

設定反映のため **PowerShell / Git Bash を再起動**。

##### A-4. コマンド名のエイリアス化

Godot の実行ファイル名が長い(`Godot_v4.6.2-stable_win64.exe`)ため、`godot` コマンドで呼べるようにする。

オプション 1: シンボリックリンク作成(管理者 PowerShell)
```powershell
New-Item -ItemType SymbolicLink -Path "$env:USERPROFILE\Apps\Godot\godot.exe" -Target "$env:USERPROFILE\Apps\Godot\Godot_v4.6.2-stable_win64.exe"
```

オプション 2: コピーして名前変更(管理者不要)
```powershell
Copy-Item "$env:USERPROFILE\Apps\Godot\Godot_v4.6.2-stable_win64.exe" "$env:USERPROFILE\Apps\Godot\godot.exe"
```

オプション 3: Git Bash で alias(`~/.bashrc` に追記)
```bash
alias godot="$USERPROFILE/Apps/Godot/Godot_v4.6.2-stable_win64.exe"
```

#### 方式 B: winget(Windows Package Manager)

```powershell
winget install --id GodotEngine.GodotEngine --version 4.6.2
```

> 注: winget の Godot パッケージのバージョン指定が `4.6.2` で利用可能か事前に確認:
> `winget search GodotEngine.GodotEngine`
>
> パッケージ提供が遅れている場合は方式 A を推奨。

### 検証

PowerShell または Git Bash を **再起動した後**:

```sh
godot --version
# 期待: 4.6.2.stable.official.<commit-hash>
```

エラーになる場合:
- `command not found`: PATH 設定が反映されていない → シェル再起動
- バージョンが違う: 旧版が PATH 上で先にヒットしている → `where godot` で順序確認

### トラブルシューティング

| 症状 | 原因 | 対処 |
|---|---|---|
| Windows Defender が「不明な発行元」と警告 | 公式署名はあるが SmartScreen に未学習 | プロパティ → 全般タブ → 「ブロックの解除」をチェックして OK。Godot は OSS で公式署名済 |
| ダブルクリックで起動しない | Visual C++ ランタイム不足の可能性 | 公式から VC++ Redistributable を導入 |
| `--headless` でエラー | グラフィックドライバ依存 | 本セッションでは GUI レンダラ不要のため `--headless` で代替可。問題があれば `--rendering-driver opengl3` を試す |

### 完了後の通知

Claude Code(本セッションまたは新規)に以下を共有:
- `godot --version` の出力
- 展開先パス

→ Claude Code は H-04(import 実行)の手順を案内する。

## H-02: GdUnit4 v5.0.4 addon 配置

### 目的
`docs/02_services/version_policy.md` §9.1 で確定した GdUnit4 v5.0.4 をプロジェクトに導入し、`tests/` 配下の `extends GdUnitTestSuite` テスト群を実行可能にする。

### 前提
- H-01 と並行可能(エディタ起動はまだ不要、ファイル配置のみ)

### 手順

#### B-1. ZIP ダウンロード

ブラウザで開く:

```
https://github.com/MikeSchulze/gdUnit4/releases/tag/v5.0.4
```

ダウンロード対象: **`gdUnit4-v5.0.4.zip`**(または `Source code (zip)` のいずれか)

> 注: v6.0.x は Godot 4.5 専用で本作の Godot 4.6.2 と非互換のため **採用禁止**(`docs/02_services/version_policy.md` §9.1 備考)。必ず v5.0.x 系を取得すること。

#### B-2. 展開とプロジェクト配置

```powershell
# PowerShell
$proj = "C:\Users\FroGr\Desktop\3D Godot Projects\FirstProjects"
$tmp = "$env:TEMP\gdunit4_extract"
Expand-Archive -Path "$env:USERPROFILE\Downloads\gdUnit4-v5.0.4.zip" -DestinationPath $tmp -Force

# zip 内構造を確認(addons/gdUnit4/ が含まれているはず)
Get-ChildItem $tmp -Recurse -Depth 2 | Select-Object -First 20

# プロジェクト addons/ にコピー
New-Item -ItemType Directory -Path "$proj\addons" -Force
Copy-Item "$tmp\addons\gdUnit4" -Destination "$proj\addons\" -Recurse -Force
```

確認:
```sh
ls "/c/Users/FroGr/Desktop/3D Godot Projects/FirstProjects/addons/gdUnit4/"
# 期待: plugin.cfg, src/, runtest.gd ... 等
```

#### B-3. プラグイン有効化

##### 方法 1: エディタ GUI(推奨・最確実)
1. Godot エディタでプロジェクトを開く(本プロジェクトを「インポート」)
2. メニュー: プロジェクト → プロジェクト設定 → プラグイン タブ
3. `GdUnit4` の「有効」にチェック
4. 自動的に `project.godot` の `[editor_plugins]` セクションが更新される

##### 方法 2: テキスト直接編集(エディタ起動を後回しにする場合)

`project.godot` の末尾(なければ追記)に:
```ini
[editor_plugins]

enabled=PackedStringArray("res://addons/gdUnit4/plugin.cfg")
```

> 注: 方法 2 を使う場合、初回エディタ起動時に正しく読み込まれることを確認。失敗する場合は方法 1 で再有効化。

### 検証

```sh
ls "/c/Users/FroGr/Desktop/3D Godot Projects/FirstProjects/addons/gdUnit4/plugin.cfg"
# ファイルが存在すること
```

H-04 で `--headless --import` 実行時に `extends GdUnitTestSuite` のテストファイル(`tests/integration/networking/replication_basic_test.gd` 等)が **エラーを出さなくなる** ことが正常動作。

### トラブルシューティング

| 症状 | 原因 | 対処 |
|---|---|---|
| `Failed to load script "res://tests/.../*.gd"` で `GdUnitTestSuite` 未解決 | addon 配置先が違う | `addons/gdUnit4/` の階層を再確認(直下に `plugin.cfg` があること) |
| エディタで「プラグインを有効化」直後にエラー | バージョン違い | 5.0.4 を再ダウンロード |
| `addons/` ディレクトリが消える | Git LFS / `.gitignore` 誤設定 | 本プロジェクトの `.gitignore` は addons を除外していないため通常は無問題。`git status` で追跡状態確認 |

### 完了後の通知

Claude Code に以下を共有:
- `addons/gdUnit4/plugin.cfg` の存在確認結果
- (任意)`project.godot` の `[editor_plugins]` セクション


| 症状 | 対処 |
|---|---|
| `Permission denied (publickey)` | SSH 鍵未登録。HTTPS に切替か `ssh-keygen` + GitHub に公開鍵登録 |

| `Lint and format` で gdformat 違反 | 該当ファイルを `gdformat` で整形してコミット |

### 期待される警告(本セッション時点で残存可能性)

本セッションでは Godot を実行できなかったため、以下の **想定済リスク** が残っている:

| 想定警告 | 推定原因 | 修正方針 |
|---|---|---|
| `Shader: 'DEPTH_TEXTURE' / 'INV_PROJECTION_MATRIX' usage` | Godot 4.6 の API 仕様差 | シェーダで `hint_screen_texture` 等の qualifier を追加、または該当ロジック簡略化 |
| `Could not load resource at path "res://addons/gdUnit4/..."` | addon 未配置(H-02 未完) | H-02 完了確認 |
| `Identifier 'GdUnitTestSuite' not declared` | 同上 | 同上 |
| `Class "NetworkManager" hides a global script class` | クラス名衝突 | 競合先を特定、リネーム |
| `Inferred type for variable could not be determined` | 型推論失敗 | 明示的型ヒント追加 |
| `.tscn: invalid sub_resource ID` | 未検出の不整合 | 該当 .tscn を Read → 修正 |
| `[Spawner] floating_node_scene is null` | 実行時警告(import では出ない) | `floating_block.tscn` 配置済のため通常は出ない |

修正後は再度 `godot --headless --import 2>&1 | tee import.log` で 0 件を確認。

### 検証

```sh
# warnings 0 件を確認
grep -cE "(ERROR|WARNING)" import.log
# 期待: 0
```

`.godot/` キャッシュが生成されていることも確認:
```sh
ls -la .godot/ | head -5
```

### トラブルシューティング

| 症状 | 対処 |
|---|---|
| `godot` がそもそも起動しない | H-01 の PATH / バイナリ確認 |
| `--headless` で `Vulkan/OpenGL` 初期化失敗 | `--rendering-driver opengl3` を追加 |
| `Cyclic resource inclusion` | `.tscn` の ext_resource 循環参照、Read で確認して修正 |
| 大量の `gdformat` 風警告 | 規約適合のため `gdformat src tests` でローカル整形 |

### 完了後の通知

Claude Code に共有:
- `import.log` の全体または ERROR/WARNING 抽出
- `.godot/` 生成確認

→ Claude Code が修正反復、warnings 0 を達成したら H-04 完了。プロト実測(T26)に進む。

### 手順

#### E-1. 各国公式 DB で「Sunken Atoll」を検索

##### E-1-A. 米国 USPTO TESS
```
URL: https://tmsearch.uspto.gov/
```
1. 「Basic Word Mark Search」を選択
2. Search Term: `"Sunken Atoll"`(クォート含む)
3. Field: `Combined Word Mark`

- 完全一致 / 類似一致の件数
- ステータス(`Live` = 有効、`Dead` = 無効)
- **Class 9**(電子ゲーム / ソフト)、**Class 41**(エンターテインメントサービス)に注目

##### E-1-B. 欧州 EUIPO eSearch plus
```
URL: https://euipo.europa.eu/eSearch/
```
1. 「Trade marks」タブ
2. Filter: Trade mark name = `Sunken Atoll`
3. Nice Class: 9, 41 を指定

##### E-1-C. 日本 J-PlatPat
```
URL: https://www.j-platpat.inpit.go.jp/
```
1. 「商標」→「商標検索」
2. 検索キーワード: `Sunken Atoll` および `スンクン アトール`(カタカナ表記候補)
3. 区分: 9 類、41 類、(必要なら)28 類(玩具)

##### E-1-D. 中国 CTM Online
```
URL: https://wcjs.sbj.cnipa.gov.cn/
```
英語インターフェース切替後 / 機械翻訳 + 商標調査:
- 検索: `Sunken Atoll`
- 中国市場では音訳の重要性が高い → 「沉没环礁」「桑肯阿托尔」等の中国語表記候補も検索

##### E-1-E. 韓国 KIPRIS
```
URL: http://eng.kipris.or.kr/
```

## H-06: `LICENSE` 著作権者プレースホルダの差替

### 目的
`LICENSE` ファイル内の `[Copyright Holder TBD]` を **法的実体名** に差替え、外部配布を可能な状態にする(`pipeline/decisions/2026-05-05_initialization_complete.md` F-04)。

### 前提
- 著作権者の決定(下記 §F-1 で意思決定)
- いずれかの段階で外部配布(プライベートアルファ含む)を行う前

### 手順

#### F-1. 著作権者の決定

| パターン | 著作権者表記例 | 適用条件 |
|---|---|---|
| 個人開発 | `Ga1or0920`(個人名フルネーム推奨、本名 or 公開ハンドル) | 1 人で開発・配布、法人未設立 |
| 個人 + 学校(共同) | `Ga1or0920 / 神戸電子専門学校`(学則に従う) | 学校 IP ポリシーに従う必要がある場合 |
| 任意団体 / サークル | `<団体名> Team` | チーム開発 |
| 法人 | `<会社名>, Inc.` または `<会社名>株式会社` | 法人設立済 |

##### 学校所属の場合の注意
- 神戸電子専門学校(または所属校)に **学生作品の IP 帰属に関する規定** があるか確認
- 授業課題の場合は学校所有が一般的、自主制作は学生本人所有が一般的(規定による)
- 不明な場合は学校事務 / 担当教員に確認(配布前必須)

##### 確定までは
- 配布しない範囲では `[Copyright Holder TBD]` のままで OK(本セッションのスカフォールド状態)
- ただし **GitHub に Public で push する場合** は配布相当のため確定が必要

#### F-2. LICENSE ファイル編集

```sh
cd "/c/Users/FroGr/Desktop/3D Godot Projects/FirstProjects"
```

ファイル `LICENSE` の冒頭付近:

```
Copyright (c) 2026 [Copyright Holder TBD]
```

を確定した著作権者表記に変更。例:

```
Copyright (c) 2026 Ga1or0920
```

または

```

```

#### F-3. プレースホルダ通知ブロックの除去

```
================================================================================
PLACEHOLDER NOTICE
================================================================================

The "[Copyright Holder TBD]" placeholder above MUST be replaced ...
(以下 4 行)
```
