# エスカレーション基準

## 1. 目的

Claude Code が **自走を中断して人間に判断を委ねる** べき状況を明文化する。判断の遅れも誤った自走も避けるため、基準を統一する。

## 2. 即時エスカレーション(必須)

以下は問答無用で人間に上げる:
1. **法務・倫理** に関わる判断(著作権、未成年向け表現、暴力表現の線引き)
2. **シークレット漏洩** の疑い
3. **配布・公開** に関わる最終決定
4. **本番データの変更**(既存ユーザのセーブ・課金履歴に影響)
5. **依存関係の重大変更**(エンジン本体・主要 SDK のメジャーアップ)
6. **契約条件の変更**(API ライセンス改定、料金大幅変更)
7. **重大な障害**(Sev1/Sev2)

## 3. 基準型エスカレーション

### 3.1 不確実性が閾値を超えるとき
- 仕様が二通り以上に解釈可能、決め手がない
- 同等の選択肢が複数あり、どれも将来へ影響する
- 既存規約と要求が衝突する

### 3.2 自動修正の上限に達したとき
- 同一ゲートを N 回連続で失敗(N はプロジェクトで決定、目安 3 回)
- 自動修正がコード規模・影響範囲を超える
- 修正の根本原因が外部要因にある

### 3.3 コスト/性能が想定を超えるとき
- 1 ジョブの予算超過
- 1 日の累計予算超過
- API レート制限の継続的超過
- ビルド時間・テスト時間が許容を超える

### 3.4 範囲外要求
- 要求が `00_overview/project_charter.md` のスコープ外
- 「対象から除外する」項目に踏み込む

### 3.5 機微表現
- 政治的・宗教的・差別的に分かれる表現
- 実在人物・組織を想起させる表現
- 倫理ガイドライン(`07_governance/ai_ethics.md`)が定める NG 領域に近い

## 4. エスカレーションの作法

1. **作業を安全に停止**(中途状態のコミットを避ける)
2. 状況サマリ(3 行)
3. 選択肢(2〜4 個)、各選択肢の影響
4. 推奨案を 1 つ、根拠付きで
5. 期限・緊急度

例:
```
[状況] ボス AI が長尺会話で Inworld 月次予算 80% に到達。あと 3 日で月末。
[選択肢]
  A: 残期間プロンプトを短縮(品質低下の可能性)
  B: ローカル LLM へ一時切替(設置時間 2h)
  C: 月次プラン引上(コスト x1.5)
[推奨] A。根拠: 品質低下は許容範囲、月またぎ後に B/C を再評価
[期限] 24h
```

## 5. ユーザの不在対応

- ユーザが応答しない場合の取扱は事前に決める
- 既定: 安全側(変更しない、配布しない、削除しない)
- 「自走承認」を事前に取った範囲は継続可

## 6. 規約違反の依頼が来たとき

1. 規約引用と該当ドキュメントへのリンク
2. 違反になる理由
3. 規約準拠の代替案
4. 例外申請手続(必要時)を示す

## 7. 倫理的に拒否する場面

- ユーザに損害が及ぶ可能性が高い行為
- 第三者の権利侵害
- 法令違反のリスク
- 強い差別的・暴力的・性的に不適切な創作物の依頼

これらは丁重に拒否し、代替の方向性を提示する。

## 8. 誤検知の取扱

- エスカレーション後にユーザが「不要だった」と判断した場合、基準を見直す
- 過剰エスカレーションも品質低下の一因と認識する

## 9. ログ

- すべてのエスカレーションは `pipeline/escalations/<date>.md` に記録
- 後で振り返り、基準改訂の材料にする
