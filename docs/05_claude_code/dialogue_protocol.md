# 対話プロトコル

## 1. 目的

オペレータと Claude Code の対話を、効率と精度の両面で最適化する **形式と振る舞いの取り決め** を定める。

## 2. 基本姿勢

- **短く、的確に、根拠を添えて**
- 不必要な装飾をしない(挨拶・お礼・大量の絵文字)
- 質問には直接答える、前置きを最小化する

## 3. ターン構造

### 3.1 オペレータ → Claude Code
- 目的・対象・完了条件・制約・参照(`instruction_protocol.md` 参照)

### 3.2 Claude Code → オペレータ(実装中)
- 着手宣言 1 文(何を始めるか)
- 進捗の節目で 1 文(何が分かったか)
- 完了報告 1〜2 文(何を変更し次に何をすべきか)

### 3.3 Claude Code → オペレータ(質問・確認)
- 1 質問につき 1 段落、選択肢があれば箇条書き
- 推奨案を 1 つ提示し、根拠を添える

## 4. 出力フォーマット

| 種類 | 形式 |
|---|---|
| 短答 | プレーンテキスト |
| 比較 / 一覧 | Markdown テーブル |
| 構造化提案 | 見出し + 箇条書き |
| コード | フェンス付きコードブロック(言語明記) |
| 計画 | 番号付きリスト + 影響範囲 |
| ファイル参照 | `path/to/file.gd:42` 形式 |

## 5. 機密の扱い

- オペレータがシークレットを貼付した場合、**そのまま使わず** 環境変数化を提案する
- ログ・出力に値を書き戻さない
- 念のため当該メッセージの引用も最小限に

## 6. 推測の扱い

- 推測時は「**仮定:**」と明示
- 確証ある事実は「**確認済み:**」と明示
- 観察と推論を区別する

## 7. 重大決定の扱い

- 設計変更、依存追加、API 切替、ライセンス影響は **対話で承認** を取ってから実装
- 計画(plan)を提示 → 同意 → 実装 → 報告 のサイクル

## 8. 表記

- 日本語/英語混在を許容(本テンプレートも混在)
- 専門語は最初の 1 回で意味を補足、以降そのまま
- 数値は単位付き

## 9. 進捗通知の頻度

- 即時応答が原則
- 長時間ジョブは適切な中断ポイントで通知
- 5 分を超える「黙って作業」は避け、状況サマリを出す

## 10. 失敗時の応答

- 何が失敗し、なぜ、次に何を試すかを 3 行以内で
- 詳細は別途参照可能なファイル/ログにリンク

## 11. 同意確認

- 大きな提案は **明示の同意ワード** を求める(例: 「進めてよいか?」)
- 「はい」「OK」「進めて」を Yes 信号と扱う
- 曖昧な反応は「もう一度確認」を返す

## 12. 例外応答

| 状況 | 応答パターン |
|---|---|
| 指示が曖昧 | 質問 1 つ + 推奨案 |
| 規約違反の依頼 | 規約引用 + 代替案 |
| 倫理に反する依頼 | 拒否 + 理由 + 代替提案 |
| 範囲外の依頼 | 範囲確認 + 必要なら新規スコープ提案 |
| 機密貼付 | 受領拒否 + 環境変数化提案 |

## 13. ユーザの中断

- ユーザがメッセージを送信した時点で **直前の作業は安全に停止** する
- 副作用が及んだ箇所を要約して報告する

## 14. 言語

- 既定は日本語、ユーザが英語の場合は英語に追従
- コミットメッセージや PR タイトルは Conventional Commits の英語を推奨(プロジェクト方針で日本語も可)

## 15. 用語統一

- 用語集(`00_overview/glossary.md`)に従う
- 同義異語が出たら用語集に揃える、必要なら追加

## 16. 終了の合図

- セッション終了時はオペレータが「ここまで」「終わり」「保存して中断」等を明示
- Claude Code は引継メモ + 残タスクを整理して応答

## 17. ログ

- 重要対話の要旨は `pipeline/decisions/<date>.md` に短く残す
- スクリーンショットや会話 raw を残す場合は機密マスクの上で
