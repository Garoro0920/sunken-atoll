# 指示プロトコル

## 1. 目的

オペレータが Claude Code に与える指示の **形式と最小情報量** を統一する。これにより指示の往復を最小化し、誤解と再作業を減らす。

## 2. 指示の最小要素

すべての指示は以下を含むことを推奨する:
1. **目的(WHY)**: なぜそれを行うか
2. **対象(WHAT)**: どのファイル/シーン/アセットか
3. **完了条件(DOD)**: どうなれば終わりか
4. **制約**: 既存規約・性能・期限・コスト
5. **参照**: 関連ドキュメント・先行 PR

例:
```
[目的] ボス戦シーンのプロトタイプを作る
[対象] scenes/levels/boss_arena.tscn(新規)
[完了条件]
  - シーンが起動し、プレイヤーが操作可能
  - ボスが 3 種の攻撃モーションを循環
  - シナリオテストでクリアまで到達できる
[制約] 既存のキャラ規約に従う、ポリ予算は asset_standards に従う
[参照] specs/features/boss_intro.md
```

## 3. 指示の粒度

- **小タスク**(数分以内に完了)は単発指示
- **中タスク**(機能 1 つ)は目的 + DoD で十分
- **大タスク**(エピック)は事前に Claude Code に **計画提示** を求めてから実行

## 4. 暗黙の前提

オペレータは Claude Code が以下を **既知** として扱ってよい:
- 本ドキュメント群すべて
- プロジェクトルートの `CLAUDE.md`
- 直近の `pipeline/decisions/`

これらに矛盾する指示が出た場合、Claude Code は確認質問を返す。

## 5. 指示の入力チャネル

| チャネル | 用途 |
|---|---|
| 対話 | 即時タスク、レビュー応答、相談 |
| spec.md(`specs/` 配下) | 仕様の単位、長期参照 |
| GitHub Issue | バグ・機能要求の起票 |
| TaskCreate(Claude Code 内部) | セッション内のサブタスク |

## 6. 指示の優先順位

1. **安全(セキュリティ・倫理・法務)**
2. **本ドキュメント群の規約**
3. **CLAUDE.md(プロジェクト固有)**
4. **直近のオペレータ指示**
5. **過去の慣行**

矛盾が生じた場合、上位の優先を Claude Code が確認質問とともに採る。

## 7. 質問・確認のテンプレート

オペレータが Claude Code に確認を促す形式:
```
@check 次の前提が正しいか確認:
  - X は Y である
  - Z は今回スコープ外
不明点があれば質問してください。続行可ならその旨を返してください。
```

## 8. ドラフト要請

```
@draft この仕様の最初の実装をドラフトしてください。
  - 想定スコープ: ...
  - 触ってよいファイル: ...
  - 触らないファイル: ...
  - 検証方法: ...
レビュー前提なので、不確実な部分は明示してください。
```

## 9. レビュー要請

```
@review この変更を本ドキュメント群の規約に照らしてレビューしてください。
  - 対象: <PR / ファイル一覧>
  - 観点: 規約・性能・テスト・ドキュメント整合
出力形式: チェックリスト + 修正提案 + 重大度
```

## 10. 実装要請

```
@implement 計画 <ID> に従って実装してください。
  - 規約遵守
  - テスト追加
  - ドキュメント更新
完了したら変更点を要約してください。
```

## 11. 取消・差戻

- 「巻き戻して」: 直前の変更を撤回(Git の reset/revert を使う)
- 「やり直して」: 同じ目的で別アプローチを取る
- 「中断して」: 即時停止、現状を要約

これらは即時応答する。長時間ジョブは適切な中断ポイントで止める。

## 12. 沈黙の扱い

- 指示なく長時間沈黙が続いた場合、Claude Code は **状況サマリ** を出して次の指示を求める
- 自走モードでは独自に進めてよいが、定期的にサマリを出す

## 13. 推測許容範囲

オペレータが許可している場合のみ Claude Code は推測で実行できる:
- 規約の枝葉(命名の細部)
- フォーマッタが扱う書式
- 自明な依存追加(プロジェクトで既出のもの)

それ以外は質問する。

## 14. 用語の使い分け

- 「修正」: 既存の不具合を直す
- 「追加」: 新しい機能/データ
- 「整理」: リファクタ、レイアウト変更
- 「検証」: 動作確認のみ、変更なし
- 「実験」: 短期、後で破棄前提

オペレータはなるべくこれらを使い分け、Claude Code は文脈から識別する。
