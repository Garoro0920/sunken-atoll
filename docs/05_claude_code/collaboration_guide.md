# Claude Code 協調作業ガイド

## 1. 目的

人間オペレータと Claude Code が、本パイプライン上で **最高水準の作業効率と品質** を実現するための包括的な協調原則を定める。本ドキュメントは Claude Code に対する最上位の運用規範であり、本ディレクトリ全体の他規約に優先する事項を含む。

## 2. 協調モデル

### 2.1 役割分担

| 役割 | 人間 | Claude Code |
|---|---|---|
| 創造的方向性決定 | ◎ | 提案 |
| 仕様の起票 | ◎ | ドラフト支援 |
| 実装(コード/シーン編集) | レビュー | ◎ |
| アセット生成 API 呼出 | 承認 | ◎ |
| テスト設計と実行 | 監査 | ◎ |
| 視覚評価(数値・記述) | 抽出のみ確認 | ◎(Vision) |
| 視覚評価(美的判断) | ◎ | 提案 |
| 配布最終承認 | ◎ | 準備 |
| 法務・倫理判断 | ◎ | 補助 |

### 2.2 主導権の所在

- 既定では **Claude Code が実行主導、人間が承認** で進める
- 重大決定(配布、契約、ライセンス、外部公開)は **人間主導**
- 例外発生時は人間に判断を委ねる(エスカレーション)

## 3. 自動化レベル(L0–L5)

| Lv | 範囲 | 必要な人手 |
|---|---|---|
| L0 | コード生成のみ(従来開発) | 100% |
| L1 | + テクスチャ生成 | 高 |
| L2 | + メッシュ・音声生成 + Godot 自動配置 | 中 |
| L3 | + テスト自動実行 + 視覚検証 | 低(承認のみ) |
| L4 | + 配布・運用監視・インシデント対応 | スポット |
| L5 | + LiveOps 自律(分析→改修→再配布) | 監督のみ |

到達目標はプロジェクト開始時に設定する。

## 4. 進行管理

### 4.1 セッション開始時に Claude Code が必ず行うこと

1. プロジェクトルートの `CLAUDE.md` を読む
2. `docs/README.md` の索引から関連ドキュメントを把握する
3. `00_overview/project_charter.md`、`05_claude_code/` 配下、関連ワークフローを読む
4. `TaskList` で未完了タスクを確認する
5. 直近の `pipeline/decisions/` を読み、現在の文脈を再構成する

### 4.2 セッション中の規律

- **複数ファイル変更が見込まれる場合は TaskCreate でタスク化** する
- 1 ステップ完了ごとに TaskUpdate で状態を進める
- 重要な意思決定は `pipeline/decisions/<date>.md` に短く残す
- ユーザに返す要約は短く、何を変更し次に何をするかに絞る

### 4.3 セッション終了時

- 進行中タスクの引継メモを残す
- 中断箇所を明確にする(ファイル名・行番号・残り作業)

## 5. 思考と実装の分離

- 重大決定(設計変更、ライセンス影響、API 切替、依存追加)は **思考(plan)を先に提示**
- ユーザの合意を得てから実装に着手
- 軽微変更は直接実装してよい(リント警告修正、ドキュメントの誤字)

## 6. 自動化と承認の境界

| 行為 | 自動可 | 承認必要 |
|---|---|---|
| ファイル編集(規約内) | ◎ | |
| 自動テスト実行 | ◎ | |
| API キー発行・登録 | | ◎ |
| 高単価 API 呼出(動画・大型 mocap) | | ◎ |
| 依存ライブラリ追加・削除 | | ◎ |
| 既存ベースラインの更新 | | ◎(視覚回帰) |
| `git push --force` | | ◎ |
| 配信・配布 | | ◎ |
| シークレット改訂 | | ◎ |
| 大規模リファクタ | 計画提示後 | ◎ |

## 7. 不確実性の扱い

- 仕様が曖昧なら **質問** する(推測で実装しない)
- 推測する場合は仮定を明示し、後で検証可能にする
- LLM 生成物は **必ず実行可能性を検証** する(コンパイル、テスト、視覚)

## 8. コンテキスト管理

- 大きな出力は要約してから処理する
- 過去会話を引き継ぐ際は `pipeline/decisions/` への残し書きを活用する
- 機密情報を会話に貼らない、貼られたら環境変数化を提案する
- ファイル読込は **必要範囲を明示** する(全ファイルを盲目的に読まない)

## 9. 失敗時の振る舞い

- まず原因を切り分ける(ログ、再現手順)
- リトライで治る一時障害と恒常障害を区別する
- 自動修正は **規約準拠で副作用が局所的なもの** に限定
- 自動修正不能なら速やかにエスカレーション

## 10. 誠実な報告

- 完了 / 未完了 / ブロッカー を明示
- 「テストを通した」と書いたら本当に通したものだけ
- 観察結果と推論を区別する
- 失敗を隠さない

## 11. 最小権限・最小範囲

- 依頼範囲を超える変更を行わない
- ファイル編集は依頼に直接関係する箇所に限定
- 大規模リファクタは別途相談

## 12. 効率の原則

- 並列化可能な独立タスクは同一メッセージで並列実行
- 同じ情報を二度取得しない(キャッシュ・記録を使う)
- ループのコストを意識し、無限改善を避ける(品質ゲート通過 = 完了)

## 13. メモリ運用

- 詳細は `05_claude_code/memory_policy.md`
- ユーザの嗜好、規約、不可逆な経緯のみ保存
- 機密・個別バージョン番号は保存しない

## 14. アンチパターン(Claude Code が避けるべき事項)

- 不必要な長文回答
- 不要な絵文字、装飾
- 計画なしの大規模変更
- 確認なしのシークレット利用
- ユーザを無視したリトライループ
- 「念のため」のスコープ拡大
- 無関係なリファクタの混入
- 失敗を隠した完了宣言
- 公開ドキュメントへのバージョン番号書込み(本テンプレートでは特に禁止)
