# セッションプロトコル

## 1. 目的

Claude Code との 1 セッション(対話の開始から終了まで)を **再現可能で引継ぎやすい** ものに統一する。長期プロジェクトの記憶喪失を防ぐ最重要規律。

## 2. セッションの種類

| 種別 | 例 |
|---|---|
| 短時間 / 単発 | バグ修正、誤字、軽微リファクタ |
| 中時間 / 機能単位 | 新機能の実装、テスト追加 |
| 長時間 / エピック | 大型機能、基盤変更 |
| 自走 / バッチ | 夜間ビルド、定期メンテ |

## 3. キックオフ手順(Claude Code が必ず実行)

1. プロジェクトルート `CLAUDE.md` を読む
2. `docs/README.md` を確認し、関連ドキュメントを読む
3. 対象ファイル / シーン / 仕様の現状を把握する
4. `TaskList` で現状を確認、必要なら新規タスクを起票
5. 直近の `pipeline/decisions/` と `pipeline/escalations/` を確認
6. 進める前に **理解と計画を 3〜10 行で要約** して提示
7. 大型変更ならユーザの GO を待つ

## 4. 進行中の規律

- 重要な節目で 1 文の進捗通知
- ファイル参照は `path:line` 表記
- 失敗・観察事項は隠さず記録
- 規約逸脱を発見したら **その場でドキュメント参照とともに警告** する

## 5. 中断対応

- ユーザ発言が来た時点で安全に作業を停止
- 中途状態のコミットは作らない(必要なら未コミットで保留)
- 状況を 3 行以内で報告

## 6. クロージング手順

セッション終了前に Claude Code は以下を出力する:

```
[今回の成果]
- 変更ファイル: 列挙(短く)
- 完了タスク: ID と要約
- マージ可能か: yes/no(品質ゲート状況)

[次の一歩]
- 残タスク: ID と最初の一手
- ブロッカー: あれば

[残記録の場所]
- pipeline/decisions/<file>: 主要意思決定
- pipeline/escalations/<file>: あればエスカレーション内容
```

## 7. 引継ぎメモ

長時間中断・別オペレータ引継ぎ・別 Claude セッション再開のため、`pipeline/decisions/<date>.md` に短い引継ぎメモを残す:

```
# YYYY-MM-DD セッションサマリ

## やったこと
- ...

## わかったこと
- ...

## 決めたこと
- ...

## 次の一歩
- ...

## 注意
- ...
```

## 8. 自走セッション(バッチ)

- 必ず開始時に **自走範囲** を明示(何をしてよく、何を待つか)
- 重大決定は実行せずキューに積む(「人間判断待ち」フラグ)
- 完了後はサマリレポートを `pipeline/decisions/<date>_autorun.md` に保存

## 9. 並走セッション

- 複数オペレータが同時に Claude Code を駆動する場合、触る範囲を分ける
- ブランチ運用(`08_process/branching_and_commits.md`)で衝突回避
- 共有ホワイトボード(Issue / 共同 spec)で進捗可視化

## 10. 長文脈の扱い

- 1 セッションの会話が長くなりすぎたら、要点を引継ぎメモに保存して新セッション
- 詳細は `context_management.md`

## 11. NG パターン

- キックオフを省略して即実装
- 完了報告に進捗の嘘や誇張を含める
- ドキュメント参照なしの大型変更
- 引継ぎメモなしの中断

## 12. 緊急事態

- ユーザから「止まれ / 中断 / 巻き戻して」が出た瞬間に止まる
- 副作用範囲を即時報告
- 巻き戻しは Git revert / reset を併用、強制系は確認後
