# サブエージェント運用(Agent オーケストレーション)

## 1. 目的

Claude Code が `Agent` ツール(サブエージェント)を起動して並列・隔離されたサブタスクを実行する際の **使い分け・指示・回収** の規律を定める。

## 2. サブエージェントの利点と代償

- **利点**: 並列化、文脈窓の節約、専門エージェント(Explore / Plan 等)の活用
- **代償**: 中での文脈は消える、結果は要約として戻る、誤解の余地

→ **「主の文脈を汚さずに、独立した調査・実装を進めたい」ときに使う**

## 3. 起動して良いケース

- **複数の独立した調査**(コードベース横断検索、複数ファイルの参照解析)
- **時間のかかる単独タスク**(検索 / ビルド検証 / テスト集計)
- **専門指向の作業**(計画策定、レビュー、セキュリティ監査)

## 4. 起動を避けるケース

- 主の文脈に直接結果を反映させる必要がある軽微作業
- 単一ファイルの編集
- 結果が短時間で取れる単純検索

## 5. ブリーフィングの作法

サブエージェントは主の対話を見ていない前提で、自己完結したプロンプトを渡す:
1. **背景**: なぜこの作業が必要か
2. **目的**: 何を達成して欲しいか
3. **入力**: どこを見ればよいか(パス・URL)
4. **既知**: 既に判明している事実、回避したい無駄
5. **出力**: 形式と長さ(「200 語以内」など)
6. **判断**: 自律的に判断してよい範囲、エスカレーションすべき事項

## 6. 並列実行

- 独立したサブエージェントは **同一メッセージで並列起動** する
- 触るファイル群が重なる場合は直列にする(衝突回避)

## 7. 結果の取扱

- サブエージェントの返答は **意図したことの説明** であり、実際にやったことの保証ではない
- ファイル変更があれば実体を確認する(Read / Diff)
- 重要な事実は主の文脈にも要約して残す

## 8. エージェント種別の使い分け

| 種別 | 用途 |
|---|---|
| 汎用 | 調査・複合タスク |
| 探索系(Explore 系) | パターンや定義場所の特定、限定的読込 |
| 計画系(Plan 系) | 設計・実装計画の策定 |
| レビュー系 | セキュリティ・規約・整合性監査 |

## 9. 隔離(Isolation)

- 副作用を伴う実験的変更は **隔離環境** で行う(worktree やブランチ)
- 隔離結果のうち取り込むものだけマージする

## 10. 失敗時

- サブエージェントが失敗した場合、原因を主が把握してから再投入
- 同じ指示で何度も再投入しない(指示を改善する)

## 11. 観測性

- 起動した目的と所要時間を `pipeline/decisions/` に短く記録
- 大規模並列を行った場合はサマリを残す

## 12. アンチパターン

- 主の文脈に置いておけば良い軽微作業を毎回サブに丸投げ
- ブリーフィング不足で文脈不明のまま放り出す
- サブの「やったつもり報告」を確認なく信じる
- 同じ目的のサブを多重起動
