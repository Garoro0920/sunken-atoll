# メモリ運用ポリシー

## 1. 目的

Claude Code の永続メモリ機能(セッションをまたぐ記憶)を **何に使い・何に使わないか** を定める。

## 2. 保存してよいもの

- ユーザの **協働嗜好**(返答の長さ、説明の深さ、確認の頻度など)
- プロジェクトの **不可逆な経緯**(なぜ A ではなく B を選んだか、過去の事故・対策)
- 公開ドキュメントに書きにくい **暗黙合意**(口頭で繰り返される判断基準)
- 外部システムへの **参照点**(どの Issue Tracker、どの Slack、どの Drive)

## 3. 保存してはいけないもの

- 認証情報・API キー・個人情報
- バージョン番号・モデル ID(本テンプレートの方針)
- コードや設定ファイルの内容(これらはリポジトリで管理)
- 一時的・短期的な状況(これはタスク or `pipeline/decisions/` で管理)
- 法的に保管すべきでない情報

## 4. 使い分け表

| 種類 | 保存先 |
|---|---|
| 人格的好み・対話スタイル | メモリ |
| プロジェクト規約 | `docs/04_standards/` |
| 設計判断の記録 | `pipeline/decisions/<date>.md` |
| バージョン採択 | `docs/02_services/version_policy.md` |
| 外部システム参照 | メモリ + `docs/06_operations/` |
| シークレット | シークレットマネージャ(`02_services/secrets_management.md`) |
| 仕様 | `specs/` |
| 障害ポストモーテム | `pipeline/postmortems/` |

## 5. 形式

メモリ項目は短く構造化:
```
[type] feedback | user | project | reference
[summary] 1 文
[why] 背景・理由
[apply when] いつ参照すべきか
```

## 6. 記憶の更新

- 規約や事実が変わったら **古い記憶を更新または削除**
- 矛盾が生じたら現実(コード/ドキュメント)を優先しメモリを修正
- 不要になった項目は積極的に削除

## 7. 期限

- 「短期」項目は使い終わったら削除
- 「中期」項目は四半期で見直し
- 「長期」項目はプロジェクト終了まで保持

## 8. プライバシー

- ユーザの個人情報・取引先情報・契約内容は保存しない
- ユーザの強い要望でない限り、雑談メモは残さない

## 9. メモリと公開ドキュメントの優先順位

- 公開ドキュメントが Single Source of Truth
- メモリは個別文脈の補助として機能
- 矛盾時はドキュメントを優先し、メモリを更新する

## 10. 漏洩リスク

- 共有環境(複数人で使う Claude Code 設定)では **共有が許される項目** のみメモリに置く
- 個人的嗜好で他者に影響するものは判断保留
