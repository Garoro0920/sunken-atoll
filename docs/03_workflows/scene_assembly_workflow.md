# シーン構築ワークフロー

## 1. 目的

生成済みアセットとコードを統合し、Godot のシーン(`.tscn`)・リソース(`.tres`)・スクリプトを構築する手順を規定する。

## 2. 起点

- 仕様書(`specs/`)に新規シーンが定義された
- 既存シーンに変更要求があった
- テスト失敗・視覚回帰不合格を受けた修正

## 3. 基本フロー

```
[1] シーン仕様の整理
      - 構成ノードの列挙
      - 必要アセット参照
      - 必要スクリプト
      - 入出力(他シーンとの連携)
[2] アセットの存在確認
      - 不足アセットは asset_generation_workflow に従い生成
[3] コード生成・配置
      - src/ 配下のスクリプトを生成または更新
[4] .tscn 生成
      - PackedScene として出力
      - ext_resource / sub_resource を整理
[5] .tres 生成(必要に応じて)
[6] ヘッドレス再インポート
[7] シーン読込テスト(GdUnit4 シーンランナー)
[8] 視覚チェック
[9] コミット
```

## 4. .tscn 編集の規律

### 4.1 直接編集と Godot エディタ編集の使い分け
- ノード追加・プロパティ変更程度の小規模変更は **テキスト直接編集**
- 大規模リファクタや UI レイアウト変更は **エディタ + 再保存**
- 直接編集後は必ず `godot --headless --check-only` 相当でロード可能性を確認

### 4.2 ext_resource の管理
- `[ext_resource]` 行の `id` は重複させない
- 不要参照は削除
- パスは `res://` から始める絶対パスで統一

### 4.3 sub_resource の管理
- 1 シーン専用なら `sub_resource` で内包
- 共有再利用が見込めるなら `.tres` に外部化

### 4.4 マテリアルの外部化
- インポート直後は組込マテリアル
- 編集する場合は **「Make External」** 相当で `.tres` に切り出して `resources/materials/` に配置
- 再インポートで上書きされないようにする

## 5. ノード命名

- 命名規約は `04_standards/naming_conventions.md`
- 役割が明確になる名詞句
- 複数同種は `Enemy_01`, `Enemy_02` のように番号

## 6. スクリプト配置

- ロジックは `src/` 配下に置き、シーンは参照のみ
- インスタンス特有の値は **エクスポート変数** でシーンから上書き
- `class_name` を必ず付与し型解決を強化

## 7. 共有データ駆動

- ゲームデータ(敵パラメータ、武器属性、ストーリーフラグ)は `resources/data/` に `.tres` として配置
- 直接コードに埋め込まない
- ローカライズ可能な文字列は `localization/strings.csv` のキー参照

## 8. シーン分割の指針

| 規模 | 対応 |
|---|---|
| 単純な小オブジェクト | 1 シーン |
| 中規模(キャラ + UI 連動) | 親シーンに子シーンをインスタンス |
| 大規模(レベル全体) | チャンク分割 + 動的ロード(`SceneTree.change_scene_to_packed`) |
| 巨大(オープンワールド) | ストリーミング、LOD、メモリ管理 |

## 9. シーン同士の通信

- **シグナル**: 子 → 親、または同階層の疎結合通信
- **オートロード(Singleton)**: グローバルイベント・グローバル状態
- **EventBus パターン**: 大規模イベントは中央バスに集約
- **直接参照**: 寿命が一致する密結合に限定

## 10. テスト連動

- シーン作成と同時に **対応するシナリオテスト** を `tests/scenarios/` に作成
- 最小限「シーンが起動する」「主要ノードが存在する」「主要遷移が動く」を検証
- 詳細は `03_workflows/testing_workflow.md`

## 11. 視覚回帰連動

- 主要シーンには **ベースライン画像** を用意
- 解像度・アスペクト比・カメラ位置を固定
- 物理・乱数を固定するテストモードを用意

## 12. アンチパターン

- 1 シーンに数千ノードを詰め込む
- 大量の `print` を残す
- インスタンス側で `_ready` に高コスト処理を入れる
- 暗黙的にグローバルへ依存する
- マテリアル設定をスクリプトで毎フレーム上書きする

## 13. 完了定義

- シーンがエディタ/ヘッドレスで正常に読み込まれる
- 関連シナリオテストが緑になる
- 視覚回帰の差分が許容範囲内
- コードレビュー(自動 + 必要に応じ人間)を通過
