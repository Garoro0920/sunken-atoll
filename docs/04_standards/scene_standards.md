# シーン規約

## 1. 目的

Godot シーン(`.tscn`)とリソース(`.tres`)の設計規律を統一する。

## 2. シーンの責務

- 1 シーン 1 責務(プレイヤー / 敵 / レベル / UI 画面 / マネージャ)
- シーンは「組み立て」の場、ロジックはスクリプトに集約

## 3. ノード階層

- 階層は浅く保つ(過深な階層は探索コスト増)
- 役割で分類: `Visual`, `Collision`, `Audio`, `AI`, `Logic`
- 不要な中間ノードを作らない

## 4. ルートノード

| 種類 | 推奨ルート |
|---|---|
| キャラクター | `CharacterBody3D` / `RigidBody3D` |
| プロップ | `StaticBody3D` / `Node3D` |
| レベル | `Node3D`(子に環境・敵・トリガ) |
| UI 画面 | `Control` |
| マネージャ | `Node` |

## 5. シーン参照

- `[ext_resource]` の `id` は重複なし、整理整頓
- 不要参照は削除
- パスは `res://` から始める

## 6. PackedScene の使い方

- 再利用予定があれば必ず `PackedScene` 化
- ランタイム生成は `preload(...)` 経由
- ホットスポットでは `instantiate()` を再利用パターンで最小化

## 7. シーンの分割閾値

- ノード数が一定を超えたら **分割を検討**(目安はプロジェクト開始時に決定)
- 1 ファイル 5,000 行を超えたら必ず分割
- 共通部分は **継承シーン** か **インスタンス子シーン** に切出

## 8. シグナル設計

- 子 → 親へは シグナル
- 親 → 子へは メソッド or プロパティ
- 同階層・他系統は EventBus
- 編集後の接続切れは CI で検出(自動テストで参照)

## 9. オートロード(Singleton)

- 真にグローバルなものに限定
- 例: `EventBus`, `GameState`, `SceneRouter`, `AudioMaster`, `Logger`
- 多用すると依存関係が見えなくなるため最小限

## 10. グループ

- ノードグループ(`add_to_group`)はメタデータ的検索に有用
- 大量参照には `EventBus` を優先

## 11. 物理レイヤとマスク

- 物理レイヤは **意味で命名**(`world`, `player`, `enemy`, `pickup`, `trigger`)
- マスクは「衝突対象」を明示
- プロジェクト設定の Physics Layer 名を必ず付ける

## 12. UI

- レイアウトは Anchor / Container ベース
- 解像度依存値は `theme` または相対値
- 入力フォーカス順序を必ず設計
- アクセシビリティ要素(フォントサイズ、色覚配慮)を考慮

## 13. リソース駆動

- パラメータは `.tres` に外部化(敵の HP、武器の威力、クエストデータ)
- スクリプトに直書きしない
- ローカライズは `localization/strings.csv` のキー参照

## 14. ロード戦略

- 起動時: 最小限の AutoLoad と初期シーン
- レベル: SceneTree.change_scene_to_packed
- ストリーミング: 大規模ワールドはチャンク単位でロード/アンロード
- ローディング表示: ResourceLoader の `load_threaded_request` で進捗

## 15. 視覚回帰連動

- 重要シーンには「視覚テスト用」決定論的バリアントを用意
- 物理停止、乱数固定、カメラ固定の `--test-mode` フラグを供給

## 16. アンチパターン

- 1 つのレベルシーンに数千の敵を直接配置(プールへ)
- AnimationPlayer を毎フレーム生成
- スクリプトでシーンの構造を頻繁に書き換える(代わりにシーン分割)
- ノード名に空白・記号を使う
