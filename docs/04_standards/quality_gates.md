# 品質ゲート

## 1. 目的

工程ごとに通過必須となる **自動チェック** を定義する。Claude Code は本ゲートを満たさない成果物をマージ・リリースしてはならない。

## 2. ゲート定義

### G1: コード受入(PR 作成時)
- リンタ(GDScript / C# / Python / TypeScript / Markdown)成功
- フォーマッタ差分なし
- 型チェック成功
- 単体テスト緑
- ビルドが通る(ヘッドレスインポート + コンパイル)
- LOC 上限ガード(肥大化検出)
- **シークレットスキャン** クリーン

### G2: 統合(main マージ前)
- 統合テスト緑
- シナリオテスト緑
- 視覚回帰差分が閾値以下、または承認済みベースライン更新付
- パフォーマンス劣化なし(主要シーン)
- 依存ライセンスチェック合格
- ドキュメント更新の整合性(変更が API/規約に及ぶ場合)

### G3: プレリリース
- 全プラットフォームビルド成功
- 各ストアの形式検査(プリフライト)合格
- リリースノート存在
- ローカライズ未翻訳キーの一覧で blocker 0 件
- 監視 SDK が組み込まれていることを自動確認

### G4: 本番リリース
- プレリリース緑
- 人間承認(PO)
- ストア審査受領
- セキュリティアドバイザリ確認

### G5: 運用継続
- クラッシュ率閾値以下
- 1% low FPS が許容内
- セーブデータ互換性検査(マイグレーション必要時のみ)

## 3. 閾値

具体的な数値はプロジェクト開始時に確定し、本ドキュメント末尾「閾値マトリクス」に追記する。例:
- LOC 1 PR あたり: 上限値
- 視覚差分: SSIM 下限値
- パフォーマンス劣化: 平均 FPS の許容低下率
- クラッシュ率: 期間あたりの上限

## 4. 例外運用

- やむを得ない例外は **承認手続き** + **期限付き** で許可
- `pipeline/exceptions/<id>.md` に理由・期限・解消条件を記録
- 期限超過は CI が必ず警告・停止

## 5. ゲートの実装位置

| ゲート | 実装 |
|---|---|
| G1 | pre-commit + PR CI |
| G2 | main 向け CI、マージ前必須 |
| G3 | release ブランチ / tag CI |
| G4 | Environment Required Reviewers |
| G5 | 監視ダッシュボード + アラート |

## 6. Claude Code の関与

- Claude Code はゲート不合格時、まず **自動修正を試行**
- 自動修正の許容範囲(規約準拠の軽微変更、フォーマッタ、決定的なリファクタ)を超える場合はエスカレーション
- 例外申請を勝手に行わない

## 7. レポート

- ゲート結果はすべて PR / リリースに自動コメント
- 失敗時は再現コマンドと推奨アクションを併記
- 視覚差分はベースラインと差分画像のリンクを示す

## 8. 改訂

- ゲート追加/緩和は重大決定として `00_overview/document_index.md` に必ず記録
- 緩和は再発防止策とのセットで提案する
