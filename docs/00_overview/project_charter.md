# プロジェクト憲章

## 本作の特定(プロジェクト適用時に記入)

| 項目 | 内容 |
|---|---|
| タイトル | **Sunken Atoll**(2026-05-05 確定) |
| ジャンル | 協力型マルチプレイ・サバイバル・クラフト(海洋・水没世界) |
| 主たる参照点 | SUNKENLAND(Vector3 Studio) — **ジャンル方向性のみ参照、固有意匠は流用しない**(`07_governance/ip_policy.md`、GDD §10) |
| 主要プラットフォーム | Windows / Steam(MVP) |
| 副次プラットフォーム | Linux / Steam Deck / macOS(MVP 後) |
| 想定同時接続 | 2〜8 人(MVP は 4 人ホスト型) |
| 中核 GDD | `specs/game_design_document.md` |

## 目的

本プロジェクトは、**Godot 4 を基盤とする 3D ゲーム開発プロセスを、Claude Code を主オーケストレータとして全自動化(または半自動化)** することを目的とする。具体的には、企画仕様(自然言語または構造化テキスト)を入力として、外部生成系 API および MCP サーバを連携させ、3D アセット・音響・コード・シーン・テスト・配布までの一連を、人間の最小限の関与で完了させる開発環境を構築する。

本作は本テンプレートの **第一適用プロジェクト** として、上記目的の実証も兼ねる。

## 背景

- 生成系 AI と Model Context Protocol(MCP)の成熟により、ゲーム制作工程の大半が API 駆動可能となった
- Godot 4 はテキストベースのシーン/リソース定義(`.tscn` / `.tres` / `.import`)とヘッドレス CLI を備え、**LLM 主導のオーケストレーションに最も適したオープンソースエンジン** である
- 個別の生成系サービスを束ねる「統合パイプラインの設計と運用規律」が、現時点で最大の差別化要因となる

## スコープ(本作向け確定版)

### 対象に含めるもの

#### テンプレート由来(基盤)
- Godot 4 を用いた 3D ゲームプロジェクトの設計・実装・テスト・ビルド・配布
- 外部生成系サービスとの API 連携(3D メッシュ、テクスチャ、HDRI、アニメーション、音響、ボイス、NPC AI)
- Claude Code による自動化・協調作業のためのドキュメント体系・規約・プロトコル
- バージョン管理(Git/Git LFS)、CI/CD、運用監視、ローカライズ、配布までの一連
- 知財・ライセンス・AI 倫理に関する最低限のガバナンス

#### 本作固有(MVP 範囲、GDD §8.1 と整合)
- 海面・水中の物理表現と専用レンダリング(水面シェーダ・水中ボリューメトリック)
- 浮体ベースの建築・拠点システム(T1〜T2 ティア)
- 自由潜水 + 簡易ダイビングギアまでの潜水アクション
- 筏 / 帆船 / 動力船(複数人同乗を主要要素とする)
- 4 人協力プレイ(ホスト型、Steam フレンド招待)
- 3 環境帯(浅瀬・半水没都市・沿岸遺跡)、海賊小集団 1 種、海生危険生物 2 種
- 派閥 1〜2 + 簡易交易、メインストーリー導入のみ
- 一部 NPC を LLM 駆動とする実験的会話システム

### 対象から除外するもの

#### テンプレート由来
- ハードウェア(コンソール SDK)固有の認可・契約手続き
- マーケティング・ユーザ獲得施策
- エンタープライズ規模の組織・人事・財務マネジメント

#### 本作固有(GDD §8.3 と整合)
- 競争型 PvP モード
- F2P 課金経済 / マイクロトランザクション
- ターン制要素
- 深海帯・潜水艇・専用サーバ・コンソール展開(MVP 後のストレッチ候補、本作スコープ外)
- Web/HTML5 配布(技術評価のみ、本作リリース対象外)

## 成功基準

### テンプレート観点(本テンプレ自体の検証)

| 指標 | 目標 |
|---|---|
| 自動化レベル | プロンプト入力からプレイ可能ビルド出力まで人手介入をスポットレビューに限定できる(L3 到達) |
| 反復速度 | 仕様変更からプレイ可能ビルド再生成まで一日以内 |
| 品質ゲート通過率 | CI による自動テスト・視覚回帰の通過率を継続的に維持できる(具体閾値は `04_standards/quality_gates.md` 末尾マトリクスで管理) |
| 再現性 | 同じ仕様・同じバージョン採択で同じ成果物が再生成可能 |
| ドキュメント完全性 | 本ディレクトリのドキュメントのみで第三者が同等のパイプラインを構築可能 |

### 本作観点(MVP リリース判定)

| 指標 | 目標 |
|---|---|
| ゲームプレイ完遂 | 4 人協力で「漂着 → T2 拠点構築 → 沿岸遺跡踏破」を 1 セッションで通せる |
| 同期品質 | RTT 200ms 以下で目立つ同期破綻なし、400ms までは許容劣化に収まる |
| 描画性能 | デスクトップ標準(1080p)で平均 60 FPS / 1% low 50 FPS 以上(GDD §7.3) |
| 安定性 | 1 セッション 2 時間でクラッシュ・進行不能・致命的同期破綻 0 件 |
| IP 独自性 | 主要意匠の商標・著作権類似性チェックを通過(`07_governance/ip_policy.md`) |
| プレイ体験 | クローズドプレイテストで「もう 1 セッション続けたい」と回答する割合 70% 以上 |

具体的な数値は GDD §7.3 と `04_standards/quality_gates.md` 閾値マトリクスで一次管理し、本表は概要として保持する。

## 想定体制

- **人間 1〜数名**: プロダクトオーナー(PO)、最終承認者、クリエイティブディレクター(CD)
- **Claude Code**: 主オーケストレータ。コード生成、シーン編集、API 呼出、テスト、レビュー、レポート
- **外部 API 群**: 各生成・推論・配信サービス(`02_services/service_catalog.md` 参照)
- **CI/CD**: GitHub Actions を中心とする自動化基盤
- **プレイテスター(本作固有)**: マルチプレイ協調動作の検証のため、MVP 段階で外部プレイテスターを 4〜8 名手配する

## 中核原則

1. **テキスト最優先**: あらゆる仕様・設定・状態を Markdown / テキスト形式で表現する
2. **再現性第一**: 同じ入力からは同じ出力が得られる構造を保つ。乱数はシード固定する
3. **API 駆動**: GUI 専用ツールはパイプラインから除外する。代替の API 駆動サービスを優先する
4. **段階的自動化**: L0 から L5 へ段階的に進める。最初から全自動を狙わない
5. **品質ゲート前進**: 検出可能な不具合は CI で必ず止める。手動でのみ通せる例外を作らない
6. **権利の明確化**: 生成物のライセンス・帰属・商用可否を必ず記録する
7. **ドキュメントが先**: 実装の前にドキュメントを更新する
8. **小さなコミット**: 変更は意味単位で分割し、コミットメッセージは LLM 解釈可能な規約に従う

## 非目標

- 完全な無人化(人間の創造性・最終承認は常に必要)
- 全エンジンへの汎用化(本プロジェクトは Godot 4 に特化する)
- 既存大規模プロジェクトへの後付け適用(新規プロジェクトでの採用を前提とする)
