# システムアーキテクチャ

## 1. 目的

本ドキュメントは、Godot 4 を基盤とし Claude Code をオーケストレータとする 3D ゲーム開発パイプラインの全体構造を規定する。各構成要素の役割、責務境界、接続方式、依存関係の俯瞰を提供する。

## 3. レイヤ責務

### 3.1 人間レイヤ
- 創造的方向性の決定、最終美的判断、契約・配布の承認、倫理的判断
- 例外発生時(エスカレーション)の意思決定
- Claude Code の提案を承認/却下し、根拠ある修正指示を返す

### 3.2 Claude Code レイヤ(オーケストレータ)
- 仕様の解釈とタスク分解
- 生成系 API の呼出、結果のプロジェクトへの統合
- Godot MCP を介した実行・テスト・スクリーンショット取得
- ファイル編集(コード、シーン、リソース、設定、CI 定義、ドキュメント)
- 結果のレポート、品質ゲートの状態通知、エスカレーション

### 3.3 生成系 API レイヤ
- 3D メッシュ、テクスチャ、HDRI、アニメーション、音響、ボイス、対話
- 各サービスは `02_services/service_catalog.md` で個別管理する
- 各 API は **冪等な呼出単位**(同一入力で同一出力)に整える

### 3.4 Godot MCP レイヤ
- Godot エディタ/ランタイムの自動制御
- 入力注入、シーン操作、スクリーンショット取得、状態取得
- テストランナーの起動、結果の収集

### 3.5 Godot プロジェクト本体(SOT)
- すべての成果物が最終的に集約される唯一の正
- バージョン管理対象
- インポート設定(`.import`)とプロジェクト設定(`project.godot`)も含む

### 3.6 CI/CD レイヤ
- インポート検証、テスト、視覚回帰、ビルド
- 品質ゲートの強制
- 配布物のアーティファクト化

### 3.7 配布・運用レイヤ
- ストア/ホスティングへの公開
- ランタイムクラッシュとパフォーマンスの収集
- 利用状況の解析

## 4. 主要原則

1. **SOT の単一性**: Godot プロジェクト本体だけが正。生成系 API の出力はあくまで素材
2. **テキスト形式の徹底**: 人間/AI の双方が編集可能な形式を選ぶ
3. **冪等性**: ワークフローはリトライ安全に設計する
4. **疎結合**: 各レイヤの差し替えが可能であること(例: 3D 生成サービスを別ベンダに切替できる)
5. **観測可能性**: 各工程の入出力をログに残し、後から再構成可能にする
6. **権利情報の追跡**: 生成物のライセンスをアセットメタデータに記録する

## 5. 受容できるリスクと境界

- **生成系 API の品質ばらつき**: 採用前にプロジェクト開始時の評価で許容範囲を確認する
- **API のレート制限と料金**: 初期段階で見積もりを行い、CI のキャッシュ戦略で抑制する
- **AI 生成物の法的不確実性**: `07_governance/` の方針に従う
- **Claude Code の幻覚**: 規約・テスト・型システム・視覚検証で多重に補足する
