# パイプライントポロジ

## 1. 目的

本ドキュメントは、生成 → 加工 → 統合 → 検証 → 配布の各工程をどのコンポーネントで実行するかを規定する。

## 2. 工程定義

| 段階 | 名称 | 主担当 | 入力 | 出力 |
|---|---|---|---|---|
| P0 | 仕様化 | 人間 + Claude Code | 自然言語 | spec.md |
| P1 | タスク分解 | Claude Code | spec.md | TaskList |
| P2 | アセット生成 | 生成系 API | プロンプト | バイナリ素材 |
| P3 | 加工・最適化 | Claude Code + Blender(任意・OSS 経由) | 素材 | Godot 互換素材 |
| P4 | プロジェクト統合 | Claude Code | 素材 + コード | `.tscn` / `.tres` / `.gd` |
| P5 | インポート検証 | Godot ヘッドレス | プロジェクト | `.import/` |
| P6 | 自動テスト | GdUnit4 + シーンランナー | テストシーン | テスト結果 |
| P7 | 視覚検証 | Godot MCP + Claude Vision | スクリーンショット | 視覚レポート |
| P8 | ビルド | Godot ヘッドレス | プロジェクト | プラットフォーム別実行ファイル |
| P9 | 配布 | CLI(butler / steamcmd / fastlane) | ビルド成果物 | 公開物 |
| P10 | 運用監視 | Sentry / 分析 | ランタイム | インシデント/メトリクス |
| P11 | フィードバック反映 | Claude Code | インシデント | 仕様/タスク更新 |

## 3. データの種類と接続

### 3.1 同期コール(秒〜分・即時待機)
- 2D 画像、SFX、TTS、Vision 解析
- 失敗時の即時リトライ可

### 3.2 非同期ジョブ(数分・ポーリング)
- 3D メッシュ生成、mocap、BGM、ヘッドレスビルド
- ジョブ ID で状態追跡。タイムアウトとリトライ上限を設定

### 3.3 ストリーム(継続)
- ランタイム NPC LLM、ボイス会話、Sentry イベント
- バックプレッシャと再接続戦略を定義

## 4. ワークフロー結合パターン

### 4.1 ファンアウト・ファンイン
新シーン構築時、複数アセットを並列生成し全完了を待ってシーン統合。
```
spec → [tripo, stability, deepmotion, elevenlabs, aiva] → wait_all → assemble
```

### 4.2 段階的整形
mocap → リターゲット → リトポ → 圧縮 → 配置の各ステップで品質ゲートを通過させる。

### 4.3 検証ループ
配置 → ヘッドレス起動 → スクショ → Vision 評価 → 不合格なら再生成。
ループ最大回数とエスカレーション条件を設定する。

## 5. 失敗時挙動

| 失敗種別 | 標準対応 |
|---|---|
| API 一時失敗 | 指数バックオフで N 回リトライ |
| API 永続失敗 | 代替プロバイダへフェイルオーバー(`02_services/service_catalog.md` で定義) |
| 品質ゲート不通過 | 自動修正試行 → 上限超過時はエスカレーション |
| 期限超過 | 部分成果でのドラフト出力 + 残作業を明示 |

## 6. レート制限・コスト管理

- 各 API の同時呼出数と日次上限をプロジェクト開始時に決定する
- 高コスト API(動画生成・大型 mocap)はキャッシュを必須にする
- 開発中は常時 dry-run モード(モックレスポンス)を提供する

## 7. オフライン能力

以下はネットワーク切断時にも完了可能であること:
- 既存アセットを使ったローカルビルド
- 単体テスト実行
- ドキュメント生成・編集
