# Definition of Ready / Done

## 1. 目的

タスクや機能が **着手可能(Ready)** か、**完了(Done)** かの判定基準を統一する。曖昧な「やった」「終わった」を排除する。

## 2. Definition of Ready(DoR)

タスク / 仕様 / Issue が以下を満たすとき、着手可能とする。

### 2.1 共通
- [ ] 目的が 1 文で説明できる
- [ ] 受入基準(observable)が箇条書きで列挙されている
- [ ] スコープ(含む/含まない)が明確
- [ ] 関連 spec / docs / Issue へのリンクがある
- [ ] 想定される影響範囲(コード / アセット / API / ライセンス)が把握されている
- [ ] 必要な権限・シークレットが用意されている
- [ ] 着手者(Claude Code or 人間)が決まっている

### 2.2 仕様(spec)固有
- [ ] ユーザストーリーがある
- [ ] 非機能要件(性能 / 規制 / アクセシビリティ等)が明示
- [ ] テスト観点が列挙されている
- [ ] リスクと未決事項が列挙されている

### 2.3 アセット生成タスク固有
- [ ] 用途・スタイル・スペック(ポリ数・解像度・尺)が定義
- [ ] 採用予定サービスとモデルが特定
- [ ] ライセンス要件が確認済
- [ ] 出力配置先パスが決定

### 2.4 実装タスク固有
- [ ] 触ってよいパス / 触らないパスが明示
- [ ] 依存タスクが解消済 or 明示的にブロック許容
- [ ] テスト計画が概ね立っている

## 3. Definition of Done(DoD)

タスク / 機能 / リリースが以下を満たすとき、完了とする。

### 3.1 タスクの DoD
- [ ] 受入基準を全て満たす
- [ ] 単体・統合テストが追加 / 更新済
- [ ] 既存テストが緑
- [ ] リンタ・フォーマッタが緑
- [ ] 関連ドキュメントが更新
- [ ] PR が Approve され、規約違反指摘なし
- [ ] CHANGELOG / リリースノート(必要時)に反映

### 3.2 機能(feature)の DoD
- [ ] タスク群がすべて Done
- [ ] シナリオテストでユーザフローが通る
- [ ] 視覚回帰がベースライン内 or 更新承認
- [ ] パフォーマンス劣化なし
- [ ] ローカライズ完了 or 未翻訳キーが blocker でない
- [ ] アクセシビリティ最低基準を満たす
- [ ] 関連 spec が「実装済」に更新

### 3.3 リリースの DoD
- [ ] 機能群がすべて Done
- [ ] G3(プレリリース)/ G4(本番)を通過
- [ ] 配布・署名・ノータライズ完了
- [ ] リリースノート公開
- [ ] 監視ダッシュボードで初期トラフィック正常
- [ ] ロールバック手順を再確認
- [ ] PO 承認

## 4. アセット生成タスクの DoD(個別)

- [ ] 受領ファイルが規定形式
- [ ] チェックサム検証済
- [ ] メタデータ JSON が `pipeline/metadata/` に保存
- [ ] ライセンスフィールドが商用可で確定
- [ ] Godot プロジェクトに配置 + インポート完了
- [ ] インポート警告なし
- [ ] 関連シーンで配置確認(必要時)

## 5. ドキュメントタスクの DoD

- [ ] 内容が他ドキュメントと矛盾しない
- [ ] リンクが切れていない
- [ ] 用語が用語集に整合
- [ ] `00_overview/document_index.md` の索引に反映

## 6. 例外運用

- DoR / DoD の項目を一時的に外すには **承認 + 期限 + 解消条件** が必要
- 例外は `pipeline/exceptions/` に記録
- DoD を緩めて出した変更には「技術的負債」タグを付与し、解消タスクを起票

## 7. アンチパターン

- 「動いたから完了」(テスト追加なし)
- 「ドキュメント後で書く」(完了として通さない)
- 「ローカルで動いたから完了」(CI 緑必須)
- 部分達成を完了扱い
- DoR を満たさないままタスク着手し、後から仕様検討で破棄
