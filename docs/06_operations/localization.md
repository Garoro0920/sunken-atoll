# ローカライズ

## 1. 目的

UI / セリフ / シナリオ / ストア表記の **多言語対応** を機械的に運用する手順を定める。

## 2. 対応言語

プロジェクト開始時に決定する。日本語・英語を起点とし、需要に応じ拡張するのが一般的。

## 3. ファイル構成

```
localization/
├── strings.csv          # ベース文字列(キー、各言語列)
├── voices/              # 多言語音声(ボイス・口パク)
│   ├── ja-JP/
│   ├── en-US/
│   └── ...
├── credits.md           # 帰属表示・素材クレジット
└── store/               # ストアページ用テキスト
```

## 4. キー命名

`<area>.<context>.<key>` 形式(`04_standards/naming_conventions.md` 参照)。

## 5. ベース言語

- 内部基盤としては英語キーを推奨(API 親和性、Godot 既定)
- 文化的ニュアンスを優先する場合は日本語もベースとして許可
- いずれを採用したかを `02_services/version_policy.md` に記録

## 6. 翻訳フロー

```
[1] 開発側で新キーを strings.csv に追加(英語/日本語のみ)
[2] CI が未翻訳キーを抽出
[3] Crowdin / Lokalise へエクスポート
[4] 翻訳者(人 / 機械)による翻訳
[5] DeepL / Claude / OpenAI 等で機械翻訳ベースを生成
[6] 人間レビュー(品質・文化・用語統一)
[7] インポートして strings.csv 更新
[8] PR レビューと CI 緑
```

## 7. 機械翻訳

- DeepL を主、LLM を補助(文脈の読みが必要な場面)
- 短文・UI ラベルは品質が安定
- 長文・物語は人間レビュー必須
- 用語集を渡し、固有名詞のブレを防ぐ

## 8. 音声多言語

- TTS で多言語生成、声優役割を維持(同一キャラの声を言語横断で統一)
- ElevenLabs Dubbing 等の多言語ダブを併用
- リップシンクは Audio2Face 等で再生成

## 9. UI 配慮

- 文字伸縮(独語などで長くなる)を見越したレイアウト
- 縦書き対応は採用時に専用設計
- フォント切替: ベース + フォールバックチェーン
- グリフカバレッジ: CJK / アラビア / キリル等を切替

## 10. 文化対応

- 色彩の意味、ジェスチャ、固有名詞の現地化
- 数値・通貨・日付フォーマット
- 祝祭日・休日を考慮

## 11. ストアページ

- 各ストアに必要な多言語フィールド(タイトル、説明、スクリーンショットキャプション)
- スクリーンショット差替が必要な言語(UI が画像内にある場合)

## 12. 法令対応

- 各国の年齢分類(IARC, PEGI, ESRB, CERO)
- 規制対象表現の差替
- プライバシー文(GDPR / CPRA / APPI 等)

## 13. 品質ゲート

- 未翻訳キー 0(blocker)
- 主要シナリオの代表セリフは人間レビュー必須
- 表示崩れ(クリップ・はみ出し)を視覚回帰で検出

## 14. メトリクス

- 言語別利用比率を分析(`monitoring.md`)
- 翻訳バグ報告フォーム
- 翻訳改善の継続フロー

## 15. アンチパターン

- 文字列をコードにハードコード
- TTS 音声の声優人格が言語間で不統一
- フォントフォールバックの未設定
- 絵文字ラベルだけで意味を伝える(視覚障害アクセシビリティを損なう)
