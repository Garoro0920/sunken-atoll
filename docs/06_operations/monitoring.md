# 監視・運用

## 1. 目的

ランタイムの **クラッシュ・パフォーマンス・利用状況** を継続的に観測し、改善・障害対応へ繋げる。

## 2. 観測対象

| 領域 | 指標 |
|---|---|
| クラッシュ | クラッシュ率(セッション/日)、ANR 率、上位エラー |
| パフォーマンス | 平均 FPS、1% low FPS、フレーム時間分布 |
| メモリ | ピークメモリ、リーク疑い |
| GPU | VRAM、ドローコール、シェーダコンパイル |
| ロード | 起動時間、シーン遷移時間 |
| ネットワーク(マルチプレイ時) | 遅延、パケット損失、サーバ稼働率 |
| 利用 | DAU/MAU、リテンション、セッション長、進行率 |
| 経済(該当時) | ARPU、コンバージョン率、購入失敗率 |
| ローカライズ | 言語別利用比率、未翻訳キー検出 |

## 3. ツール

- クラッシュ・例外: Sentry(Godot 公式 SDK)
- 行動分析: GameAnalytics / PostHog / Amplitude
- サーバ運用(マルチプレイ): DataDog 等
- 配布側のレポート: ストア提供のダッシュボード

## 4. SDK 組込

- 起動直後に初期化、ユーザ ID は擬似化
- 個人情報を送らない(地域・言語・端末モデル等の最小限)
- オプトアウト導線をユーザに用意

## 5. ダッシュボード

- 主要指標を 1 画面で俯瞰できる「Single Pane of Glass」を作る
- リリース直後は別タブで「リリース直後ダッシュボード」を持つ
- 時系列・端末別・地域別・言語別フィルタ

## 6. アラート

| アラート | 条件 |
|---|---|
| クラッシュ率上昇 | 過去 N 時間平均比 +X% |
| 重大エラー新規 | unique fingerprint の新規発生 |
| サーバ稼働率低下 | しきい値割れ |
| パフォーマンス劣化 | 主要シーンで 1% low FPS が下回る |
| 経済不審 | 売上の異常変動 |

通知先は チーム チャンネル + オペレータ。

## 7. リリースとの関連付け

- リリースタグを Sentry / 分析の「Release」に登録
- 新規エラーがどのリリースで初発か即時に把握
- リリースノートにも反映

## 8. インシデント連動

- アラート発火 → `03_workflows/incident_response_workflow.md` 起動
- Sentry Issue は Claude Code(Sentry MCP)が初期トリアージ可

## 9. ログ

- クライアントは構造化ログ(JSON)推奨
- レベル: debug / info / warn / error / fatal
- 製品ビルドの debug は既定 OFF
- ユーザ言語/地域/解像度/モデルを共通フィールドに

## 10. プライバシー / コンプライアンス

- 収集データの一覧を `07_governance/` 系で公開
- 同意の必要な地域(EU 等)は明示同意フローを用意
- データ最小化と匿名化を徹底
- 子供向け配信時の追加規律(該当時)

## 11. 容量と保持

- ログ保持期間はプロジェクト方針で決定
- 個人特定可能データは早期削除
- 集計データは長期保持してもよい

## 12. 復旧訓練

- 監視ダッシュボードを使う **障害模擬訓練** を年 1 回以上
- アラート → 一次対応 → ポストモーテム まで通す

## 13. 改善ループ

- 週次/月次で指標を振り返り、改修バックログに反映
- A/B テストやフィーチャーフラグで仮説検証
