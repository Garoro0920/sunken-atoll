## 1. ゲームコンセプト

### 1.1 テーマ
**「沈んだ世界で、誰かと生き直す」**

海面上昇によって既存文明の大半が水没した近未来を舞台とする、協力型のサバイバル・クラフト・建築ゲーム。プレイヤーは漂流者となり、群島化した世界の浅瀬・水中遺跡・深海を舞台に、仲間と分業して生存・拠点強化・拡張を行う。

### 1.2 ターゲット・プレイ体験
プレイヤーが感じる中核の楽しさを優先順に定義する。

1. **協力による達成感**: 1 人では困難な探索・建築・防衛を仲間と分担して成立させる
2. **発見の喜び**: 海中遺跡やコンテナの中の希少資源・物語片を見つける
3. **拠点が育つ実感**: 浮体集落が時間とともに拡張・装飾されていく可視的成長
4. **危険管理の緊張**: 酸素・暗闇・嵐・襲撃の中で「いつ撤退するか」の判断
5. **物語との関わり**: 派閥との取引・敵対・支援を通じて世界の見え方が変わる

### 1.3 差別化要素(着想元との明確な違い)

| 観点 | 本作 | 着想元(典型的サバイバル・クラフト) |
|---|---|---|
| マルチプレイ位置付け | **協力前提** で設計(2〜8 人) | 単独優先、Co-op は付加 |
| ロール分担 | スキル + 装備で「潜水士・技師・戦士・調理・建築」を緩く誘導 | 全員が万能 |
| 海面・潮汐 | 周期的潮位 + 嵐イベントで**動的に水没/露出**するエリア | 海面はほぼ静的 |
| NPC 対話 | 一部 NPC を **LLM 駆動**(`02_services/service_catalog.md` L10)で派閥取引・噂を生成 | 固定スクリプト |
| 派閥関係 | 行動による**動的な評判系**(交易/略奪) | 固定陣営 |
| アートトーン | **ウェット PBR + 海中ボリューメトリック**で「湿った世界」を強調 | 様々 |

### 1.4 ターゲットプレイヤー
- サバイバル・クラフトジャンルの経験者
- フレンドと数十時間規模を遊びたい層(セッション 2〜4 人想定が中心)
- 海洋・水中表現に惹かれる層

### 1.5 トーン・アートディレクション
- 全体トーン: **湿潤・退廃・微かな希望**(ハードコアな絶望は避ける)
- 配色: 青緑〜灰青を基調、拠点発展で暖色アクセント増加
- 表現規範: `07_governance/ai_ethics.md` §5 に従う(過度な暴力・差別表現禁止)

## 2. 世界観設定

### 2.1 時代背景
- 設定年代: 大水没から数十年後の近未来
- 大水没の原因は**作中で完全には明示しない**(極端な気候変動 + 大規模災害の複合という曖昧な背景に留め、政治的特定を避ける — `07_governance/ai_ethics.md` §5.2)
- 既存文明の建造物は水中に多数残存。半水没のビル・橋梁・港湾・船舶・住宅地が探索対象

### 2.2 物理環境

| 区分 | 特徴 | プレイヤー影響 |
|---|---|---|
| 浅瀬・群島 | 安全度高、基本資源(木材・布・低品質金属) | 序盤拠点候補 |
| 半水没都市 | 中リスク、生活物資・部品・武器素材 | 中盤探索 |
| 沿岸遺跡 | 高リスク、レア部品・電子・化学薬品 | 中〜終盤 |
| 深海帯 | 最高リスク(暗闇・酸素・水圧)、最希少資源・物語片 | 終盤、要装備 |
| 汚染海域 | 体力減少 + 機材腐食 | 専用装備で踏破 |

#### 動的環境イベント
- **潮汐**: ゲーム内時間で周期的に水位が変動。低潮時のみ侵入可能な遺跡を用意
- **嵐**: 発生中は航海危険、視界悪化、雷被害。警告 → 帰還判断のミニドラマを生む
- **濃霧**: 視界縮小、海上敵が接近しやすい
- **海生危険生物の回遊**: 期間限定で特定海域の難度上昇

### 2.3 勢力構造

| 勢力 | 立ち位置 | 行動原理 | 関係性 |
|---|---|---|---|
| 漂流者(Player) | 主役 | 生存・再建 | — |
| 海賊団(複数小集団) | 主敵対 | 略奪 | 戦闘・撃退 |
| 旧文明残党 | 中立 | 文明再興・知識保全 | 交易・依頼 |
| 孤立島民 | 中立寄り | 自給自足 | 物々交換 |
| 海洋生物群(NPC) | 環境 | 縄張り・捕食 | 戦闘・素材 |

派閥との関係は**動的評判パラメータ**で管理。略奪行為は孤立島民との関係を悪化させる、等。

### 2.4 資源分布(原則)
- **再生資源**(漁・採集・栽培): 生存維持の主軸、拠点周辺で安定確保
- **回収資源**(漂流物・遺跡): 中核クラフトの主材料、探索が必要
- **希少資源**(深海・遺跡深部・派閥取引): 終盤装備・拠点高度化に必須

希少資源の入手難度を**距離 + 深度 + 警備**で多軸化し、単純な「奥に行くほど良い」を避ける。

### 2.5 物語フック
- ロアは**強制せず・読みたい人に届く**設計(発見可能なログ、ボイス、壁書き)
- 主軸 1 本のメインストーリー(任意進行) + 派閥クエスト + サンドボックス自由行動
- マルチプレイ前提のため、**1 人がストーリーを進めても他プレイヤーが置き去りにならない**設計とする(進行はワールド共有 + 個別任意)

## 3. コアゲームループ

### 3.1 マクロループ(複数セッション規模)
```
        ┌──────────────────────────────────────────┐
        ▼                                          │
[拠点強化] → [探索範囲拡大] → [新資源帯到達] → [新技術解放] → [脅威増加] → 再投資
        ▲                                          │
        └──────────────────────────────────────────┘
```
プレイヤーが「次の目標」を常に複数(短期 / 中期 / 長期)持っている状態を維持する。

### 3.2 セッションループ(1 プレイ 1〜3 時間)
```
ログイン → 拠点点検 → 役割協議 → 出航 → 探索/採集/戦闘 → 帰還 → 整理・保存 → ログアウト
```

### 3.3 マイクロループ(分単位)
```
[周辺観察] → [リスク評価] → [行動選択(採集/潜水/戦闘/通信)] → [進捗 or 撤退判断]
```

### 3.4 設計原則
- **撤退判断**を主要な意思決定として常に成立させる(満タン背負って戻るか、もう一歩奥に行くか)
- **協力で初めて完遂できるアクション**を各層に最低 1 つ用意(後述 §4.6)
- **失敗のリカバリ**を準備する(全滅 → 装備喪失 → ベース帰還 → 再装備)

## 4. プレイヤーアクション体系

### 4.1 移動
| 手段 | 解放条件 | 用途 |
|---|---|---|
| 歩行 | 初期 | 陸地・拠点 |
| 水泳 | 初期 | 浅瀬移動 |
| 自由潜水 | 初期 | 短時間の水中(§4.5) |
| 簡易筏 | 初期クラフト | 近距離島間移動 |
| 帆船 | 中盤 | 中距離・複数人乗船 |
| 動力船 | 中〜終盤 | 高速・長距離 |
| 潜水艇 | 終盤 | 深海帯到達 |

ボートはマルチプレイで**複数人同乗**を主要要素とする(操舵・見張り・砲撃の役割分担)。

### 4.2 戦闘
- **近接武器**: 銛・斧・修理可能なナイフ等(序盤主軸)
- **遠距離武器**: 弓・スリング → 改造火器(中〜終盤)
- **設置物**: トラップ・タレット(拠点防衛)
- **回避・防御**: スタミナ管理、装備重量による機動性差
- 戦闘は**主役ではない**(資源獲得・防衛・襲撃イベントが文脈)

### 4.3 クラフト
- 階層: **採集素材 → 精製素材 → 部品 → 完成品**
- 各階層に対応するクラフト設備(作業台・炉・電子工房等)
- レシピは**発見ベース**(文書回収・分解・実験)で解放
- 上位クラフトほど**設備・電力・希少資源**を要求

### 4.4 建築
- ベースは**浮体構造**(海上 + 浅瀬可)
- 構造物は **基礎 → フレーム → 壁/屋根 → 装飾/機能** の積層
- 機能設備: 淡水化・蓄電(風力 / 太陽光)・農園・調理・治療・倉庫・防衛
- **マルチプレイ協調**: 建築許可エリア、共有設計図、複数人同時建築
- スナップ + フリー配置のハイブリッド(`04_standards/scene_standards.md` の Anchor 設計に準拠)

### 4.5 潜水
- 自由潜水: 酸素ゲージ + 水圧で深度制限
- 装備拡張: シュノーケル → 簡易ダイビングギア → 高圧スーツ → 潜水艇
- 視界: 深度・濁度・ヘッドライトで制御
- **危険要素**: 酸素切れ、海生捕食者、浮上時の減圧(終盤要素)
- **協力要素**: 1 人が潜って 1 人が監視 / 引き上げ役という分業を装備で誘導

### 4.6 協力要素(各層に最低 1 つ)
| 層 | 単独可 | 協力で初めて完遂 |
|---|---|---|
| 探索 | 浅瀬探索 | 深海帯(監視役 + 潜水役) |
| 戦闘 | 雑魚海賊 | 拠点襲撃イベント(複数方向同時防衛) |
| 建築 | 小屋 | 大型構造物の桁渡し・梁 |
| 航海 | 筏 | 動力船(操舵・見張り・銃座) |
| クラフト | 単一品 | 高度設備(複数同時操作) |

### 4.7 入力マップ(初期定義)
- 移動 / カメラ / インタラクト(長押しで選択肢)
- 武器スロット切替(ホイール or 数字)
- ジェスチャ(指差し・呼びかけ・手助け要請)— マルチ協調の中核
- ピン(地図への目標共有)
- 入力詳細は `resources/input_maps/` で定義(後続タスク)

## 5. 進行システム

### 5.1 サバイバル要件(プレイヤーが管理する状態)
| 状態 | 説明 | 失敗時 |
|---|---|---|
| 体力 | ダメージで減少 | 死亡(装備落下) |
| 空腹 | 時間経過で減少、食事で回復 | 体力減少 |
| 喉の渇き | 早く減る、淡水化必須 | 体力減少 |
| 体温 | 雨/夜/水中で低下 | 体力減少・速度低下 |
| 酸素 | 潜水時のみ | 即時体力減少 |
| 汚染暴露 | 汚染海域・腐敗食で蓄積 | 持続デバフ |

数値とバランスは別仕様(`specs/features/survival_balance.md`)で詳細化。

### 5.2 成長要素
- **スキル**: 行動による成長(潜水時間・銃精度・建築速度・農耕効率 等)
- **装備**: 段階的アップグレード、修理可能、消耗あり
- **知識(レシピ)**: 文書発見・分解・購入で解放
- **拠点ティア**: 拠点規模・設備によるロック解除(高ティア = 高度クラフト可)

### 5.3 拠点発展
| ティア | 主要解放 | 必要素材帯 |
|---|---|---|
| T1 仮拠点 | 寝床・倉庫・調理・淡水化(手動) | 浅瀬資源 |
| T2 定住地 | 発電・自動水化・小規模農園・防壁 | 半水没都市資源 |
| T3 集落 | 工房群・タレット・通信・大型船坞 | 沿岸遺跡資源 |
| T4 港湾 | 派閥誘致・貿易・大規模設備 | 派閥取引・深海資源 |

### 5.4 リスク管理
- **強襲イベント**: 海賊襲撃 / 嵐 / 海生大型生物 — 警告期間付き
- **腐敗・耐久**: 食料・装備・建材は時間で劣化、メンテが日常タスク
- **資源枯渇**: 近場で同じ採集を続けると獲得量低下、拠点を移すか遠出
- **死亡ペナルティ**: 装備落下 + 一定時間の脱力(リスク評価を強制)

## 6. マルチプレイ要件

### 6.1 トポロジ(2 形態を想定)
| 形態 | 用途 | サーバ |
|---|---|---|
| ホスト型(P2P + リスニングサーバ) | 友人内プレイ | プレイヤーの 1 人がホスト |
| 専用サーバ | 常時稼働コミュニティ・大規模 | クラウド配置 |

採用バックエンド候補は `02_services/service_catalog.md` L16(Nakama / Edgegap / GodotSteam)。具体採択は `02_services/version_policy.md` 確定後。

### 6.2 同期方式
- **権威モデル**: ホスト or 専用サーバ権威。クライアントは予測 + 補正
- **ステート同期**: ワールドの可破壊状態・建築物・インベントリは権威側で永続化
- **イベント同期**: 戦闘・採集の決定論的処理を意識(`03_workflows/testing_workflow.md` シナリオテスト要件と整合)
- **エリア・関心管理**(AOI): 遠方プレイヤーの細かな同期は間引き

### 6.3 セッション設計
- 同時接続: **2〜8 人を MVP**(将来的に 16 人を検討)
- セッション継続: ホスト切断時の**ホストマイグレーション**(難度高、MVP は再接続要求でも可)
- 招待: Steam フレンド招待 / 招待コード(専用サーバ)
- セーブ: 権威側に世界状態を定期保存(`06_operations/distribution.md` クラウドセーブ別途)

### 6.4 ロール分担(緩やかな誘導)
**全員が全機能アクセス可能**としつつ、装備・スキル・所持容量で分業を促す。

| ロール | 得意 | 装備例 |
|---|---|---|
| 潜水士 | 深海探索・サルベージ | ダイビングギア・サルベージツール |
| 技師 | クラフト効率・修理 | 工具・予備部品 |
| 戦士 | 防衛・狩猟 | 武器・装甲 |
| 建築家 | 設計効率・素材消費低減 | 設計ツール・運搬具 |
| 調理 / 農 | 食料・薬品 | 調理具・採集ツール |

ロールはランタイム自由切替可(セッション中の事故・離脱に強い設計)。

### 6.5 セーブ・復帰
- ワールド状態は権威側永続化
- 個人インベントリは**ワールドにバインド**(ワールド A から B にキャラを持ち出さない MVP)
- 中断・再参加: 数日空けても復帰可能

### 6.6 反チート / 公平性(MVP は最小)
- 権威サーバ採用により基本的なチートは抑制
- 入力検証はサーバ側で実施
- 公開専用サーバはオーナー管理(コミュニティ規約に準ずる)
- 詳細は本作リリース前に別仕様化

## 7. 技術的制約・前提条件

### 7.1 ネットワーク
- 想定 RTT: ≤ 200ms で快適、≤ 400ms で許容
- 帯域: クライアント上り 30〜100 KB/s、下り 100〜300 KB/s 目安
- パケット欠損: 5% まで補正で吸収
- NAT 越え: STUN/TURN 構成または Steam Relay
- 採用候補: Nakama(セッション・状態) + Edgegap(ホスティング) + GodotSteam(Steam 統合)
- バージョン採択は `02_services/version_policy.md` で決定後にロック

### 7.2 アセット仕様
- 形式: GLB / glTF 2.0 を第一推奨(`04_standards/asset_standards.md`)
- マテリアル: PBR(ORM パック)、**水面 / 水中ボリューメトリック専用シェーダ**を別途設計
- ライティング: 屋外昼夜サイクル + 水中減衰モデル
- LOD: 浮体・建築・船舶・大型構造物すべて LOD0/1/2 必須
- アニメーション: ヒューマノイド共通スケルトン(`04_standards/asset_standards.md` §6.3)
- 音響: 水中フィルタ(low-pass + reverb)、距離減衰、3D ポジション

#### アセット生成パイプラインへの要求
本作の世界観上、**水没・腐食・湿潤**な質感が大量に必要となる。`03_workflows/asset_generation_workflow.md` の生成系ワークフローでプロンプト雛形を別途整備する(例: "barnacle covered, wet, rust, partially submerged")。

### 7.3 パフォーマンス要件(目標、開始時に正式値を `04_standards/quality_gates.md` 閾値マトリクスへ反映)
| プラットフォーム | 解像度 | 平均 FPS | 1% low |
|---|---|---|---|
| デスクトップ高 | 1440p | 60 | 45 |
| デスクトップ標準 | 1080p | 60 | 50 |
| デスクトップ低 | 1080p | 30 | 25 |
| Steam Deck | 720p | 40 | 30 |

#### 描画コストの主要懸念
- 水面シェーダ(リアルタイム反射 / 屈折)
- 水中ボリューメトリック散乱
- 浮体物理(多数オブジェクト)
- 大規模建築物の同時描画(LOD + ストリーミング必須)

### 7.4 プラットフォーム
- 第 1: **Windows / Steam**(MVP)
- 第 2: Linux(Steam) / Steam Deck
- 第 3: macOS
- 将来: コンソール(検討)、Web(技術評価のみ、MVP 対象外)
- 配布チャネル詳細は `06_operations/distribution.md` 参照

### 7.5 物理
- 採用候補: **Jolt Physics**(海上多数浮体に有利) — 確定は `version_policy.md`
- 大規模衝突体は階層化(船 = 複合 + 単純化形状)
- 物理は**部分的に決定論的**(マルチで再現性確保のため固定 tick)

### 7.6 アクセシビリティ(MVP 最低)
- カラーブラインド配慮(派閥色は形状でも区別)
- 字幕(セリフ・効果音)
- 入力リマップ
- 文字サイズスケール
- 詳細は `04_standards/scene_standards.md` §12 と `06_operations/localization.md`

### 7.7 既知のリスク

| リスク | 重大度 | 対策方針 |
|---|---|---|
| 水面・水中シェーダの性能負荷 | 高 | 早期にプロトタイプを作りベンチマーク |
| マルチプレイ同期の複雑性 | 高 | MVP はホスト型のみで成立させる |
| 浮体物理の安定性 | 中 | Jolt 採用 + 簡略化衝突 + tick 固定 |
| LLM NPC のレイテンシ・コスト | 中 | 主要 NPC のみ LLM、雑魚は固定スクリプト |
| IP 類似性のクレームリスク | 高 | §10 のガード遵守、独自ブランディング徹底 |
| 海中のオクルージョン難 | 中 | 距離フォグ + LOD で前提化 |

## 10. ライセンス・IP 上の留意事項(必読)

本作は SUNKENLAND を**ゲームジャンルとデザイン方向性の参照点**として用いるが、以下を厳守する(`07_governance/ip_policy.md`、`07_governance/licensing.md`、`07_governance/ai_ethics.md`)。

### 10.1 厳守事項
- **タイトル・ロゴ・キャラクタ・固有名詞・固有資産・コード・テクスチャ等は一切流用しない**
- 「SUNKENLAND の」「SUNKENLAND ライク」等の表記は**マーケティング・ストア記述で使用しない**(社内設計議論内のみ可)
- AI 生成プロンプトに `SUNKENLAND` その他既存タイトルの直接名指しを**含めない**(模倣的出力リスクのため)
- 既存実在ブランド・人物・組織を想起させる固有表現を避ける
- 採用する生成系サービスの利用規約と学習データ条項を確認(`07_governance/ai_ethics.md` §4)

### 10.2 ジャンル参照は許容
- ジャンル(海洋サバイバルクラフト)、メカニクスの一般的構造(採集→クラフト→拠点→戦闘)、世界観モチーフ(水没文明)は**業界共通の表現空間**であり、独自意匠で再構築する分には問題ない。

### 10.3 確認手続
- 主要意匠(タイトル・ロゴ・主要キャラビジュアル)は商標・著作権類似性チェックを PO 承認前に実施
- 不明な意匠類似性は**法務助言を要請**(`05_claude_code/escalation_policy.md` §2.1 — 即時エスカレーション)
