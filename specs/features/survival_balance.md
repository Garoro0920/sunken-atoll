## 1. 目的

プレイヤーが管理する状態(体力・空腹・喉・体温・酸素・汚染暴露)の **数値モデルとバランス基準** を定義し、データ駆動で調整可能な形で実装する。

## 2. ユーザストーリー

- プレイヤーとして、生存状態を一目で把握し、優先順位のある管理ができる。
- ゲームデザイナとして、コードを変更せず `.tres` 編集だけでバランスを調整できる。
- 協力プレイヤーとして、仲間の生存状態を共有・支援できる。

## 3. 要件

### 3.1 機能要件
- 6 系統の状態(下表)を独立にシミュレート
- 状態は `PlayerSurvivalState` リソース(`.tres`)として保持
- 派生効果(速度低下・視界低下・連鎖ダメージ)を状態しきい値で発火
- マルチプレイで自分の状態を仲間に共有(数値ではなく段階表示)

### 3.2 状態テーブル(初期案、調整前提)

| 状態 | 範囲 | 自然減衰(/分) | 致命しきい値 | 主な回復手段 |
|---|---|---|---|---|
| HP | 0–100 | 0(被ダメ駆動) | 0 で死亡 | 包帯・薬・休息 |
| 空腹 | 0–100 | -0.5 | <10 で HP 減 | 食事 |
| 喉 | 0–100 | -1.0 | <10 で HP 減 | 飲料水(淡水化必須) |
| 体温 | -100〜+100 | 環境依存 | ±70 で HP 減 | 焚火・衣服・日陰 |
| 酸素 | 0–100 | 潜水時 -10 | 0 で HP 急減 | 浮上・装備 |
| 汚染暴露 | 0–100 | -0.2(自然回復) | >70 で HP 減 + デバフ | 洗浄・薬 |

実数値は `resources/data/balance/survival.tres` で管理し、本表は初期目安。

### 3.3 派生効果

| 状態しきい値 | 効果 |
|---|---|
| 空腹 < 30 | 移動速度 -10% |
| 喉 < 30 | スタミナ回復 -50% |
| 体温 < -40 | 微小持続ダメ + クラフト不可 |
| 体温 > +40 | 微小持続ダメ + 集中力(精度)低下 |
| 酸素 < 20 | 視界に黒ビネット |
| 汚染 > 50 | 視界揺れ・スタミナ最大 -20% |

### 3.4 非機能要件
- 状態更新は固定 tick(物理 tick と同期、`Engine.physics_ticks_per_second`)で決定論的
- マルチプレイ同期: 状態更新は権威側、クライアントは UI 表示のみ
- パフォーマンス: 1 プレイヤーあたり毎 tick CPU < 0.05 ms
- ローカライズ: 状態名・効果説明はローカライズキー化(`localization/strings.csv`)

### 3.5 テスト観点
- 単体: 各状態の減衰・回復・しきい値発火
- 統合: 複数状態の同時管理(例: 空腹 + 寒さ + 潜水)
- シナリオ: 「無対策で 30 分放置 → 空腹由来死亡」「水分補給なしで 20 分行動 → 喉由来死亡」「深海で酸素切れ → 死亡」
- 視覚: HUD のしきい値変化が正しく表示

## 4. 非要件 / スコープ外

- 病気システム(感染・治療フロー)は本仕様の対象外、別 spec
- スタミナ系(行動制限)は別 spec(`specs/features/stamina_combat.md` 予定)
- 食料の腐敗・耐久は別 spec(`specs/features/decay_durability.md` 予定)

## 5. 受入基準(DoD)

- [ ] 6 系統の状態が `PlayerSurvivalState` で動作
- [ ] バランス値が `.tres` で外部化、コード再ビルド不要で調整可能
- [ ] 単体テスト: 各状態の遷移を検証(緑)
- [ ] シナリオテスト: 上記 §3.5 の死亡 3 シナリオが期待通り進行(緑)
- [ ] HUD で状態が視覚的に分かる(視覚回帰ベースライン登録)
- [ ] マルチプレイで権威同期(同期テスト緑)
- [ ] ローカライズキー登録(英・日)

## 6. 想定実装(Claude Code 向けヒント)

- 配置: `src/gameplay/survival/`、`scenes/characters/player.tscn`(コンポーネント追加)
- 触ってよいパス: 上記 + `resources/data/balance/`、`tests/unit/survival/`、`tests/scenarios/survival/`、`localization/strings.csv`
- 触らないパス: `src/networking/`(同期は既存基盤を利用)、`src/core/`(原則変更不可)

## 7. リスクと未決事項

- バランス調整が長期化する可能性 → 早期からプレイテスト
- 多状態 UI が画面を圧迫する可能性 → 段階表示と詳細展開のハイブリッド設計
- 体温計算における環境同期(夜・雨・水中)の重さ → 簡略モデルから開始
