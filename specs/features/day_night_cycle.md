# Spec: 昼夜・天候・潮汐サイクル

| 項目 | 内容 |
|---|---|
| 状態 | Draft |
| 親 GDD | `specs/game_design_document.md` §2.2 / §1.3 |
| 起票日 | 2026-05-05 |
| 関連 spec | `water_shader.md`(海面パラメータ駆動)、`survival_balance.md`(体温)、`boat_navigation.md`(風)、`combat.md`(視認性) |

## 1. 目的

ゲーム内時間に基づく **昼夜サイクル + 天候 + 潮汐** を実装し、世界の動的演出と戦略要素(GDD §1.3 差別化要素 3「動的な海面変動・潮汐」)を提供する。

## 2. ユーザストーリー

- プレイヤーとして、昼間に探索し夜間は拠点でクラフト・休息するリズムが自然に生まれる。
- 嵐の警告が出たら帰港 / 帆を畳む判断ができる。
- 低潮時にだけ侵入できる遺跡があり、潮汐を読んで計画する。

## 3. 要件

### 3.1 時間モデル

- ゲーム内時間: 1 リアル分 = 1 ゲーム時間(調整可、データ駆動)
- 1 ゲーム日 = 24 ゲーム時間 = 24 リアル分(目安)
- 永続化: ワールド時刻はホスト権威でセーブに含む

### 3.2 昼夜サイクル

| 時間帯 | ゲーム時刻 | 視覚 |
|---|---|---|
| 夜明け | 5:00〜7:00 | 淡橙、霧 |
| 日中 | 7:00〜17:00 | 高彩度、青空 |
| 夕暮れ | 17:00〜19:00 | 赤橙、低い太陽 |
| 夜 | 19:00〜5:00 | 暗青、月光 |

実装: `DirectionalLight3D` 角度 + 色温度を時間関数で駆動。`WorldEnvironment` の Sky / 環境光も連動。

### 3.3 天候

| 天候 | 確率(時間別) | 効果 |
|---|---|---|
| 晴 | 60% | 標準 |
| 曇 | 20% | 視界やや低下、太陽弱 |
| 雨 | 12% | 視界低下、体温減少、樽水補給 |
| 霧 | 5% | 視界大幅低下、海賊接近を許す |
| 嵐 | 3% | 高波、強風、雷、視界悪化 |

天候遷移はマルコフ連鎖(現在の天候から次への確率テーブル)。決定論的シードで再現可能。

#### 嵐イベント
- 警告: 5〜10 ゲーム分前に空が暗くなる、風が強まる(プレイヤーへの帰港判断機会)
- 持続: 10〜30 ゲーム分
- 影響: `boat_navigation.md` §3.5、`building_system.md` §3.2(浮体不安定化)、`water_shader.md`(波振幅・風駆動)

### 3.4 潮汐

- 周期: 12 ゲーム時間(2 周期 / 日)
- 振幅: 平均水位 ±2m(調整可)
- 効果:
  - 浅瀬の露出 / 水没(歩行可・不可の切替)
  - 一部遺跡入口が低潮時のみ開放
  - 浮体拠点の係留・桟橋の高低差
- 表示: HUD で次の干潮 / 満潮までの時刻

### 3.5 風

- 風向: 数時間スケールで緩やかに変化、嵐中は急変
- 風速: 0〜30 m/s、嵐で 30+ m/s
- 共有: `boat_navigation.md` §3.4、`water_shader.md`(波)で参照

### 3.6 サバイバル連動

- 夜間 / 雨天: 体温低下(`survival_balance.md` §3.2)
- 夜間: 海生捕食者の活発化
- 嵐: 大型海生生物の接近確率上昇

### 3.7 マルチプレイ整合

- 時刻 / 天候 / 潮汐 / 風はホスト権威で同一
- クライアントへ周期的に同期(1 ゲーム分ごと、補間)
- セーブ復帰時に時刻継続

### 3.8 非機能要件

- 時刻更新: 毎フレーム実行(軽量計算)
- 天候遷移計算: 1 分に 1 回でよい
- 潮汐 / 風の更新: 1 秒に 1 回
- 同期帯域: < 50 B/s(ほぼ無視可)

### 3.9 テスト観点

- 単体: 時刻関数、潮位関数、マルコフ天候遷移(シード固定)
- 統合: 嵐イベント発火 → 視覚・物理・サバイバルへ伝搬
- シナリオ:
  - 24 ゲーム時間のサイクル全フェーズが視覚的に正常
  - 嵐警告 → プレイヤー帰港判断猶予を確認
  - 低潮時のみ遺跡入口開放
- 視覚: 各時間帯の baseline 4 枚 + 嵐 1 枚を `tests/visual/baseline/dnc/`

## 4. 非要件 / スコープ外

- 月相サイクル(MVP 対象外)
- 季節変化(MVP 対象外、ストレッチ)
- 雷の物理ダメージ詳細(MVP は直撃のみ単純判定)
- 雪・凍結(舞台が温暖海域のため不要)

## 5. 受入基準(DoD)

- [ ] 24 時間サイクルが視覚的に動作
- [ ] 5 天候の遷移が動作
- [ ] 嵐警告 → 嵐 → 解除のフルフローが動作
- [ ] 潮汐サイクル + 低潮時遺跡開放が動作
- [ ] 風が `boat_navigation` / `water_shader` と同期
- [ ] マルチプレイで時刻・天候・潮汐の同期破綻なし
- [ ] 視覚 baseline 5 枚登録

## 6. 想定実装

- 配置: `src/core/world/time_of_day.gd`、`src/core/world/weather.gd`、`src/core/world/tide.gd`、`scenes/levels/world_environment.tscn`(共有)
- 触ってよいパス: 上記 + `resources/data/world/`、`tests/unit/world/`、`tests/integration/world/`、`tests/scenarios/world/`、`tests/visual/baseline/dnc/`
- 触らないパス: `src/networking/` 基盤(同期 API のみ利用)、各種他 spec の実装本体(イベント受信のみ)

## 7. リスクと未決事項

| リスク | 対策 |
|---|---|
| 嵐イベントの頻度バランス | データ駆動 + プレイテスト |
| 視界低下時の戦闘不公平感 | UI ヒント(レーダー的索敵)で緩和検討 |
| 潮汐演出の物理コスト(海面メッシュ高さ更新) | `water_shader.md` の波関数に潮位オフセットとして加算 |
| マルチプレイ同期粒度の設計 | 1 ゲーム分ごとで十分か実測 |
| マルコフ遷移のシード共有(マルチで全員同じ天候) | ホスト権威で乱数生成 |
