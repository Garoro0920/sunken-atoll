# Spec: 派閥関係システム

| 項目 | 内容 |
|---|---|
| 状態 | Draft |
| 親 GDD | `specs/game_design_document.md` §2.3 / §1.3 |
| 起票日 | 2026-05-05 |
| 関連 spec | `combat.md`、`ai_npc_dialog.md` |

## 1. 目的

プレイヤー行動が派閥との関係性を **動的に変動** させる仕組みを提供し、世界が「動いている」感覚と長期目標を生む。GDD §1.3 差別化要素 5「動的な評判系」の中核実装。

## 2. ユーザストーリー

- プレイヤーとして、派閥を支援したり略奪したりすると、その派閥との関係性が変わる。
- 良好な派閥には交易・依頼を依頼でき、敵対派閥には襲撃される。
- 仲間と派閥への対応方針を協議できる(マルチプレイ協調要素)。

## 3. 要件

### 3.1 派閥定義(MVP)

| 派閥 | 立場 | 初期評判 | 行動原理 | MVP 採用 |
|---|---|---|---|---|
| 漂流者(プレイヤー) | 主役 | — | — | ✓ |
| 海賊団 | 主敵対 | -50(敵対寄り) | 略奪 | ✓ |
| 孤立島民 | 中立 | 0 | 自給自足、警戒的 | ✓ |
| 旧文明残党 | 中立寄り | +10 | 文明再興、知識保全 | ストレッチ |
| 海洋生物群(NPC) | 環境 | N/A | 縄張り・捕食 | ✓(感情なし) |

### 3.2 評判パラメータ

- 範囲: -100(完全敵対)〜+100(同盟)
- 永続化: ワールドセーブに含む(`multiplayer_session.md` §3.3)
- 派閥間関係マトリクス: `resources/data/factions/relations.tres`(`.tres` データ駆動)

### 3.3 評判変動イベント

| イベント | 影響 |
|---|---|
| 派閥員を殺害 | -10 |
| 派閥拠点で略奪 | -20 |
| 派閥の依頼達成 | +15 |
| 派閥に物資贈与 | +5 / 取引価値あたり |
| 敵対派閥を撃退 | +5(同派閥関係改善) |
| 時間経過(自然減衰) | 月 1 で絶対値が 1 縮小(中立化) |

数値はバランス調整対象、`resources/data/factions/reputation_events.tres` で外部化。

### 3.4 評判段階効果

| 評判 | 段階 | 効果 |
|---|---|---|
| 70〜100 | 同盟 | 共闘、価格優遇、専用クエスト |
| 30〜69 | 友好 | 通常取引、依頼受託 |
| -29〜29 | 中立 | 限定取引、警戒 |
| -69〜-30 | 敵対 | 取引拒否、見たら攻撃の可能性 |
| -100〜-70 | 完全敵対 | 領域内で常時襲撃 |

### 3.5 マルチプレイ整合

- 評判はワールド単位(プレイヤー個別ではない、ホスト権威)
- 1 人の略奪が他全員に影響(協力プレイの戦略要素)
- 評判変動はクライアントへ通知(UI 反映)

### 3.6 LLM NPC 連動

- 主要 NPC(`ai_npc_dialog.md`)に評判を `context.player_reputation` として渡す
- 高評判の NPC は寛容な発言、低評判は警戒・拒絶
- 派閥代表 NPC は評判段階に応じ会話分岐

### 3.7 非機能要件

- 評判変動イベント発火: 同 tick 内で完了、CPU < 0.1 ms
- 派閥データのシリアライズ: < 5 KB
- UI 反映: イベント発生から 1 秒以内

### 3.8 テスト観点

- 単体: 評判加減算、段階遷移
- 統合: イベント駆動(殺害 → 評判低下 → AI 行動変更)
- シナリオ:
  - 海賊と中立を維持して終盤まで進行
  - 海賊と完全敵対し襲撃頻度上昇を確認
  - 孤立島民への依頼達成 → 友好化 → 専用クエスト開放
- LLM 統合: 同じ NPC が評判段階別に異なる応答(モック評価)

## 4. 非要件 / スコープ外

- 完全な派閥戦争シミュレーション(派閥同士の動的戦闘)
- 派閥への入隊・脱退システム
- プレイヤー個別評判(MVP はパーティ共有)
- 派閥固有経済(価格変動)

## 5. 受入基準(DoD)

- [ ] 3 派閥(海賊・孤立島民・海洋生物)が動作(旧文明残党はストレッチ)
- [ ] 評判イベント 6 種が動作
- [ ] 評判段階別 AI 行動が切替
- [ ] LLM NPC への context 渡しが動作
- [ ] シナリオテスト 3 種が緑
- [ ] セーブ・ロードで評判が永続

## 6. 想定実装

- 配置: `src/gameplay/factions/`、`resources/data/factions/`、`src/ai/npc/faction_aware_ai.gd`
- 触ってよいパス: 上記 + `tests/unit/factions/`、`tests/scenarios/factions/`
- 触らないパス: `src/networking/` 基盤、`src/ai/llm_npc/`(連携 API のみ)

## 7. リスクと未決事項

| リスク | 対策 |
|---|---|
| 派閥関係の調整が長期化 | 早期プレイテスト、データ駆動で迅速変更 |
| マルチプレイで「他プレイヤーの行動による不公平」 | 投票 / 警告 UI で意思決定共有 |
| LLM NPC との一貫性(派閥認識ずれ) | context に明確な evidence list を含める |
| 評判段階の遷移演出が不足 | UI 通知 + 環境音による段階提示 |
